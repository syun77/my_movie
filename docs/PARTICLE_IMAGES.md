# パーティクル画像

2026-11-19作成。ユーザー要件は「パーティクル系の演出の各粒子に画像素材を適用できること」。追加の確定要件は「画像の指定がない場合は既存の形状で演出を行うこと」。2026-11-19に本設計の実装を承認。以下の設定・操作を実装する。

## 基本方針

画像の指定がない場合は、各演出の既存の形状・色・発光表現で描画する。新規作成時、画像の指定前、画像の解除後も演出を継続し、粒子を非表示にしない。この動作はプレビューと動画出力で共通とする。

既存の粒子運動と、粒子の見た目を分離する。雪なら花びら、火の粉なら葉、光の粒子なら星など、同じ運動へ任意の静止画を適用する。

現在の実装は演出ノードごとに画像を1枚指定し、その演出の全粒子へ共通適用する。「粒子ごとに画像を個別編集する」UIは設けない。光の粒子の複数発生源も画像は共有する。配置素材とは別の画像を選べ、透明な空クリップでも利用できる。

| 対象 | 画像へ切り替えた場合の動き |
| --- | --- |
| 光の粒子 | 発光点と追従粒子の軌道・大きさの差・明滅を維持。先頭の発光点も同じ画像にする |
| 火の粉 | 上昇・横風・揺れ・寿命による出現と消失を維持 |
| 雪 | 落下・横揺れ・奥行きによる大きさと濃さの差を維持 |
| 光の粒子2 | 粒ごとの軌道・拡縮・速度を維持。画像自体の回転は独立設定にする |

八芒星、ワープ航行、集中線、フレアなど、個々の粒子インスタンスを持たない生成演出は初期対象に含めない。

## 操作

各対象の詳細へ「粒子の見た目」を追加する。

- 表示方式: 「標準」「画像」。新規・既存プロジェクトとも初期値は標準。
- 画像: サムネイルと名前、「素材から選択」「画像を読み込む」「解除」。既存素材では静止画だけを選択可能にする。新規読込は画像として検証して素材管理へ登録し、タイムライン配置は作らない。
- 初回の画像選択成功時に画像方式へ切り替える。取消・読込失敗では元の設定を保持する。標準へ戻しても画像参照と画像用設定は保持する。「解除」は参照を外して標準へ戻す。
- 画像サムネイルへのファイルドロップは静止画1枚のみ。タイムラインへの従来の素材ドロップと区別する。
- プレビュー用サムネイルは市松背景で透明度を確認できるようにする。

| 画像用設定 | 範囲・初期値 | 意味 |
| --- | --- | --- |
| 大きさ | 1〜1000px・32px | 1080p基準の画像矩形の長辺。粒ごとの既存サイズ比を乗算する |
| 角度 | −180〜180°・0° | 画像中心を軸にした基準角度 |
| 回転ばらつき | 0〜180°・0° | 粒ごとに固定した±範囲の角度差 |
| 回転速度 | −360〜360°/秒・0°/秒 | 正は時計回り。粒子の位相を保持する時計で評価する |
| 色 | 元画像／演出色・元画像 | 元画像はRGBを保持。演出色は元画像RGBへ演出の色を乗算する |
| 合成 | 通常／加算・通常 | 紙片などの実体と発光表現を選択する |

画像用の大きさは既存の標準粒子用直径と別に保持し、方式切替で既存の直径やキーを書き換えない。共通の粒子倍率を定義し、標準描画と画像描画が同じ倍率を利用する。光の粒子2にもこの画像用大きさを提供する。

数値は共通DragValueFieldの直接入力・ドラッグ・中クリック初期化・Shift微調整・Esc取消に対応する。大きさ・角度・回転ばらつき・回転速度はノード単位のキーと音楽同期に対応。ドラッグ中は仮描画、確定時に1回保存・Undo登録する。方式・画像・色方式・合成方式は離散設定とし、現在の実装で時間変化させない。

元画像色のときは演出の色・彩度を保持して入力を無効化する。演出色は光の粒子の循環色、火の粉の暖色、雪の白、光の粒子2の粒別色・彩度を使用し、白い芯や光のにじみは追加しない。既存の濃さ・明るさ・寿命フェードは両方式へ適用する。加算合成では明るさを光量、通常合成では表示率として扱い、0で完全に消える。方式切替で数値を変更しない。

## 画像と描画

- 対応形式は既存の静止画デコーダーで扱えるものとする。動画・Spine・連番・アニメーション画像の再生は対象外。複数フレーム画像は先頭フレームの静止画として扱うことを選択画面に示す。
- EXIF等の向きを補正し、元の縦横比・透明度を保持する。矩形全体を描き、円形マスクや標準粒子の星・光芒・ハローは重ねない。透明余白も画像矩形に含め、自動でトリミングしない。
- アルファのない画像は矩形背景も表示する。黒背景を自動透過しない。透過PNG等の利用を選択画面で案内する。
- 画像中心が既存の粒子座標となる。基本変形によって粒子だけを素材へ追従させる変更は行わず、各演出の画面座標系を使う。
- 固定seedと粒番号から回転ばらつきを決定する。回転は既存の位相時計を使い、シーク順・再生速度・プレビューfpsに依存させない。左トリム・コピーで同じ時刻の見た目を保持し、個数変更でも既存粒番号の向きを変えない。
- 画像の向き補正・リニア色変換・premultiplied alphaを既存素材経路と統一する。透明端の黒縁、上下反転、加算光の二重alpha乗算を避ける。
- 通常合成の重なり順は発生源順→粒番号順で固定する。画像ごとに描画順を並べ替えない。

演出チェーンの生成ノードとして画像粒子を直前の結果へ合成する。後段のブラー・色調補正・マスク・シェイクは粒子画像も含めた結果を処理する。最終クリップ不透明度と段間マスクも共通適用する。加算光と透明中間面の扱いは [EFFECT_CHAIN.md](EFFECT_CHAIN.md) の契約に揃える。演出チェーンの共通生成ノード経路でプレビューと出力へ適用する。

## 素材管理と欠損

画像は既存VisualAssetのstillを参照し、演出内に絶対パスや画像バイナリを直接保存しない。同じ素材を配置と複数演出で共有できる。

素材参照の列挙を共通化し、配置本体だけでなく演出ノードの粒子画像も対象にする。素材管理の使用表示は「配置数」「粒子画像での使用数」を区別し、OFFや標準へ戻して保持中の参照も含める。

- 素材管理からの置換は全参照へ反映。粒子画像に使われている素材を動画・Spineへ置き換える操作は拒否する。
- 演出内で別画像へ変更した場合はそのノードだけを変更する。
- 使用中素材の削除は、配置削除と粒子画像参照解除の影響を示して確認する。粒子画像参照のためだけに利用しているクリップ本体は削除しない。参照解除時は標準へ戻す。元素材ファイルは削除しない。
- 欠損時は参照を保持し、UIに警告する。プレビューは該当画像粒子だけを非表示とし、標準粒子へ自動置換しない。置換・再読込で復旧できる。
- 出力対象区間にある有効ノードが画像方式の場合は、出力前に画像の存在・種類・デコードを検証する。欠損なら出力を止めて素材名と使用クリップを示す。OFF・標準方式・全体バイパス・未配置素材の欠損は止めない。時刻ごとの不透明度が0かどうかを欠損判定の条件にしない。
- クリップのコピーは粒子画像参照を含む。別プロジェクトへの貼り付けは参照先で素材を登録・対応付けし、ノードID・キーIDを更新する。素材パスの再基準化は既存AssetReferenceと同じ規則を使う。

## 保存・負荷・実装境界

共通のParticleAppearance値を4種類のEffectNodeに持たせ、種類別payloadとともに保存する。外観とノードの自動化所有者を揃え、種類別モデルへ同じ設定を重複実装しない。方式、保持中の画像assetID、画像用大きさ、角度、回転ばらつき、回転速度、色方式、合成方式を保存し、自動化は既存のノード所有方式を使う。画像参照がない場合は標準方式へ正規化し、既存の形状で描画する。存在するがstillではないIDはモデル検証で拒否する。参照先ファイルの欠損はモデル破損と区別する。

保存形式はv13、読込はv13〜16。v12→13の境界で粒子ノードへ標準方式・固定既定値を付与し、見た目を保持する。新規乱数を移行中に生成しない。

画像は粒ごとにデコード・アップロードせず、素材ごとのテクスチャをインスタンス描画で共有する。画像粒子用は長辺2048pxを上限とする専用縮小表現とし、配置画像の高解像度キャッシュを置き換えない。キャッシュキーに素材世代・デコード寸法・色空間を含め、置換や外部変更の再読込で更新する。

プレビューと出力は同じ画像表現と描画処理を使う。非同期読込はプロジェクト・素材・ノードの世代を照合し、取消や削除後の結果を適用しない。出力は検証後の素材を予算内で固定し、メモリ不足・デコード失敗を透明表示で黙って継続しない。

主な変更範囲はImageEffects/EffectChain、EffectAutomation/ImageParameter、ImageEffectsEditor、素材参照列挙とVisualTrack/VisualEditor/VisualAssetLoader、プレビュー/出力の画像取得、MetalSceneRenderer/Scene.metal、プロジェクト移行・履歴・クリップボード。読込・検証・キャッシュをUIやシェーダーへ重複実装しない。

## 受入条件

1. 4演出で同じ透過画像を適用でき、各演出の軌道・フェードを維持する。先頭発光点・複数発生源も確認する。
2. 非正方形・透明余白・半透明端・EXIF回転・不透明背景を持つ画像で、縦横比・向き・サイズ・色が正しい。
3. 元画像色／演出色、通常／加算、画像用各数値のキー・音楽同期・初期化・取消がプレビューとMP4で一致する。
4. 同時刻への異なる順序のシーク、左トリム、個数変更、コピー、Undo/Redo、保存復元で粒子の対応と位相を保持する。
5. 画像未指定・解除後・画像参照のない保存データの読込時は既存の形状で演出を継続する。標準への切替と再選択で設定を保持し、解除・素材削除・置換・欠損復旧・別プロジェクト貼り付けが一貫する。
6. 粒子画像だけに使う素材を使用中として検証でき、有効時だけ欠損で出力を止める。保存移行で既存の標準粒子が変わらない。
7. チェーン順序変更・クリップ不透明度・マスク・空クリップを確認し、1080p/3段/最大粒数/最大発生源でGPU時間とメモリを計測する。2048px上限の画質と負荷は実測後に確定する。

複数画像のランダム割当、出現率の重み、スプライトシート、動画粒子、速度方向への自動整列は後続の拡張候補とする。

## 検証上の制約

2048px上限はプレビュー/出力共通の実装値。画像矩形の長辺指定は粒別倍率の適用前の値であり、先頭発光点等はそれより大きくなる。光の粒子2の基準サイズは60pxとし、既存の粒別サイズをその比率で適用する。巨大な粒をさらに拡大した場合の解像感は元画像と2048px表現に依存する。

実装時のMacで1080p・3段・各4発生源×200粒のGPU時間を測定する。最小対象Macでの負荷保証とピークメモリ計測は別途必要。出力時の128MiB上限は固定するデコード済み画像の合計であり、GPUテクスチャ・中間描画面を含むアプリ全体の上限ではない。
