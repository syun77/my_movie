# Spine素材の配置・再生設計

更新: 2026-11-14。状態: 初期範囲は実装済み、全体対応は拡張設計。物理ON・特殊blendなどは未実装。

ユーザー要件はSpineの通常ランタイムで実現できる再生機能をMV Studioへ組み込むこと。以下の既定値・範囲・導入順は設計上の提案であり、実装済みの仕様と区別する。

初期実装の優先範囲は [SPINE_PHASE1.md](SPINE_PHASE1.md) を参照する。ユーザー指定のatlas・移動/回転・凸形/凹形マスクを先に実装し、提供された4.3.26モデルを受入対象とする。本書の物理ON・全blend等は後段を含む全体設計であり、初期描画検証の前提ではない。

## 1. 採用する範囲

Spineで制作・エクスポートしたモデルを画像・動画と同じVisualTrackの3段へ配置し、主音声に同期して表示、MP4へ出力する。独立した編集タブや独自アニメーション制作エンジンは作らない。

| 項目 | 初期対応 |
| --- | --- |
| 入力 | Spine 4.3エクスポートのJSONまたは.skel、.atlas、atlasが参照するPNGページ |
| 再生 | 1クリップにつき1アニメーション、1スキン、ループまたは終端保持 |
| 時間 | 素材開始位置、0.1〜16倍の固定速度、左右トリム、任意シーク |
| 表示 | 透過、region/mesh、ウェイト変形、表示順、クリッピング、標準の制約・スライダー |
| 合成 | Spine内部のnormal/additive/multiply/screen。モデルを1素材として既存の変形・不透明度・色調補正・追加演出へ渡す |
| 物理演算 | 明示的なON/OFF。初期OFF、ONは固定刻みで再計算 |
| 編集連携 | 自動保存、Undo/Redo、コピー/貼り付け/複製、素材管理・置換 |
| 音声 | 主音声のみ。Spineイベント内の音声は再生・出力しない |

対象外: .spine制作ファイルの直接読込、リギング・キー編集、モデル内ボーンの数値編集、複数トラックの混合、アニメーション間クロスフェード、スキンの組合せ編集、イベントによる外部処理、モデル内部パラメーターの音楽同期、逆再生、可変速度。ランタイムに機能があっても初期UIでは公開しない。外側の位置・拡大率などは既存の音楽同期を利用できる。

## 2. ランタイムとビルド

公式spine-cpp 4.3を採用し、初期実装は405f43295b5832e86d9df3a80beb6bc9df772312へ固定している。4.1/4.2/betaなど他形式を自動変換しない。インポート時にエクスポートバージョンを確認し、4.3以外は再エクスポートを案内する。同じ4.3でも固定したランタイムでロード・描画を検証し、未対応を黙って無視しない。

SwiftPMにC++ターゲットSpineRuntimeと、薄いSpineBridgeを追加する。Swiftからはopaque handleとC互換データだけを扱う。公式4.3のC APIを優先利用し、描画データのコピー・所有権・エラー変換などアプリ固有部分だけをブリッジへ置く。実際の固定コミットの公開ヘッダーに合わせ、API名を確定する。

- ThirdPartyへ必要なソースとライセンスを同梱し、ビルド時のネット取得を不要にする。参照元・コミット・変更有無を記録する。
- SwiftPMのC++コンパイル設定、macOS 14、arm64/x86_64を確認する。別ゲームエンジンやJavaは追加しない。
- C++例外・ポインターをSwiftへ漏らさず、失敗をエラーコード＋メッセージへ変換する。
- build-app.shで新シェーダーと第三者ライセンスをアプリへ含める。テスト後の最終コードでappを生成する。

ランタイムのソース公開は無条件利用を意味しないが、有効なSpine Editorライセンスを持つ開発者による組み込み・独自機能を持つ製品の配布は公式規約第2節に定められている。ライセンス本文と第三者表示を同梱する。アクティベーションコードはアプリやリポジトリへ保存しない。

## 3. 素材の読込と参照

「＋素材を配置…」にSpineを追加する。.json/.skel選択後、同名.atlasを候補にする。見つからない場合や別名の場合はatlas選択を求める。.json拡張子だけでSpineと断定しない。.spineを選んだ場合はランタイム用エクスポートが必要と説明する。

1. skeletonとatlasを読み、atlas内の全ページの相対パスを解決する。
2. PNGデコード、ページ寸法・region参照、モデルバージョン、アニメーション名と尺、スキン名を検証する。
3. 全依存ファイルを検証してから登録する。失敗時は半端な素材やクリップを追加しない。
4. アニメーションは一覧先頭、スキンはdefault（なければ一覧先頭）。アニメーションのないモデルは初期対応では拒否する。

素材は参照方式でコピーしない。モデルとatlasを別々のAssetReferenceで保存し、PNGページはatlas基準の相対参照とする。ネットワークURL・絶対ページパス・選択したatlasフォルダの外へ抜けるページ参照は拒否し、フォルダ内へ再出力するよう案内する。atlas自体は任意フォルダから選べる。

依存一式の更新を検出するrevisionを持つ。ファイルサイズ・更新日時は変更検出に使い、出力前は内容を読み直して検証し、内容ハッシュを記録する。設定変更とは別にモデル再読込を用意し、外部変更で再生中のデータを途中から差し替えない。

欠損モデル・atlas・ページは参照と配置を保持し、素材管理から復旧する。使用中の欠損・未対応は出力停止、未配置素材は警告のみ。読込サイズ・頂点数・PNG展開量・Metal最大テクスチャ寸法を検査し、予算超過は理由を表示して拒否する。初期の素材データ/atlas展開キャッシュ予算は合計256MiBを提案し、GPU中間ターゲットは別に計測する。

## 4. 永続モデル

現在のVisualAssetKind（still/video）にspineを追加し、VisualContentにspine(SpinePlayback)を追加する。名前だけを頼りに動画用sourceInの分岐へ混ぜない。

| 所有先 | 保存内容 |
| --- | --- |
| VisualAsset | skeletonの既存reference、spine用atlasReference、対応バージョン、固定した基準矩形 |
| SpinePlayback | animationName、skinName、sourceIn、speed、loop、physicsEnabled |
| VisualClip | 共通start/end、fixedValues/curves/audioModulations、effects |

アニメーション一覧・各尺・スキン一覧・依存ページ一覧はロード結果として保持する。保存したメタデータだけで実ファイルの有効性を判断しない。C++ handle、GPUリソース、解析途中の状態は永続化/Undoスナップショットへ入れない。

初期実装でProjectFileをversion 8へ更新した。version 7以前は既存のバックアップして新規作成する経路を使い、黙って上書きしない。過去設計書の「version 7実装済み」は現在の事実として残す。

素材置換は全使用クリップを仮検証し、同じ名前のアニメーション/スキンと必要区間を解決できる場合だけ一括確定する。不一致を先頭アニメーションへ勝手に変更しない。新素材として登録してクリップ別に選び直す経路も用意する。クリップ単位の素材変更は選択配置だけへ適用する。

## 5. 時間と配置の規則

曲時刻t、配置開始s、素材開始o、速度vに対して、未折返し素材時刻u = o + (t-s)×v。表示区間は既存と同じ[s, end)。主音声時刻を唯一の基準とし、タイマー回数で再生位置を進めない。

- ループON（既定）: アニメーション尺Dが正ならuをDで折り返す。物理演算の経過は折り返さない。
- ループOFF: u > Dは最終ポーズを保持する。物理ONならそのポーズに対して揺れの計算を継続する。
- D=0: 0秒のポーズを保持し、剰余演算を行わない。
- sourceInは有限の0以上で、ループの周回数・終端保持後の経過を含む未折返し秒として保存する。ループOFFや尺0でもDで制限しない。ポーズの参照時刻だけをDで制限し、物理経過uは維持する。ループ切替はsourceInを変更しない。終端保持・ループとも配置長は素材尺では制限しない。
- 配置初期長は2秒、次の配置/曲末で切り詰める。最小1/30秒と同段衝突検証・スナップは共通処理を使う。
- 本体移動はsourceInを保持する。左トリムはsourceIn += 開始差×speedとして見えていた動きを保持し、ループでも周回数を保持し、正規化しない。ループOFFでもDで制限せず、終端保持中の物理状態を保持する。左へ伸ばす場合の下限はsourceInが0になる位置とする。
- 右トリムは再生内容を維持して表示終了だけを変更する。
- 速度・アニメーション変更は配置長を維持する。動画の「使用素材区間を保って配置長変更」とは区別する。終端保持/ループがあるためSpineは配置長を変える必要がない。
- アニメーション変更ではsourceInを0へ戻し、スキン変更では維持する。共通変形キーと演出は維持する。

モデル内モーションは素材時間、既存の外側の手動キー・音楽同期・粒子は曲時間を使う。初期のSpineに自動拡大パルスは追加しない。手動で音楽同期を追加できる。

## 6. ポーズ評価と物理演算

SpinePoseProviderが専用actor/直列実行環境でランタイムを所有する。ロード済みの不変データは同じ環境内で共有できるが、Skeleton/AnimationState/rendererはクリップごと・プレビュー/出力ごとに独立させる。C++インスタンスを複数スレッドから同時操作しない。

### 物理OFF（初期）

セットアップポーズと選択スキンを基準に、指定した1アニメーションを要求時刻で評価し、物理更新を無効にしてworld transformを計算する。前回表示ポーズへ上書きし続ける実装を避け、履歴に依存しない。IK/path/transform/sliderなどの通常制約は実行する。イベント・音声コールバックは外へ発火しない。

### 物理ON

物理は通常のランタイム機能を使うが、任意時刻へtrack timeだけを代入しても状態は再現できない。初期方式は次のとおりとする。

1. アニメーション0秒のセットアップ状態から開始し、素材時間の1/60秒刻みでアニメーション適用・skeleton時刻更新・物理/world transform更新を行う。0秒以前のウォームアップはしない。
2. 完了した固定刻みの状態を正規状態とする。要求時刻が刻み間の場合は直前刻みのポーズを使う（最大1/60素材秒の量子化）。描画用の端数deltaを正規状態へ混入させない。
3. 順再生は同じ固定ステップ列を継続する。後方シーク・設定/revision変更は状態を作り直して先頭から再計算する。sourceInも0秒からの計算に含める。
4. ループ境界でも物理を毎周リセットしない。任意時刻へ移動する際も同じ開始状態と同じ未折返し経過から再計算する。
5. 物理はモデル内の動きにだけ反応する。MV Studioの外側の位置/回転/音楽同期はモデルの物理へ入力しない。

これはSpine Editorの可変delta再生と完全一致させる約束ではなく、MV Studio内のプレビュー・シーク・出力を同じ規則へ揃える仕様。同一環境で許容差内の一致を検証し、異なるCPU/GPUでビット単位の一致は要求しない。

長時間シークは処理量が大きい。最新要求1件へ集約し、計算途中で取消を確認する。主音声を止めて「Spineを準備中」を表示し、近似した別時刻のポーズを正解として表示しない。再計算を無言で打ち切らない。チェックポイントは初期実装に含めず、必要なら物理内部状態を完全復元できることを検証してから追加する。ポーズだけを保存して物理復元済みと扱わない。

## 7. 描画と既存パイプラインへの接続

VisualRenderLayerをframe(既存画像/動画)とspine(不変の描画パケット)のenum入力へ整理する。VisualFrameへ無理にダミーCGImageを入れない。VisualFrameProviderは画像/動画/Spineを段順へ統合し、共通時刻のスナップショットとして渡す。

描画パケットは公式SkeletonRendererが生成する順序付きコマンドをコピーしたものとし、頂点・UV・明暗色・index・texture page ID・blend mode・revisionを保持する。ランタイム所有の一時配列ポインターをactor境界へ渡さない。対応コミットのtint black等の頂点属性も欠落させない。クリッピングの形状処理は公式ランタイムへ任せる。

MetalSceneRendererにSpineMetalRendererを接続し、透明な中間ターゲットへ三角形を描く。そのテクスチャを既存のCore Image/変形/色調補正/ブラー/ブルーム/不透明度の経路へ渡す。粒子は既存どおり同段の画面座標で描く。

- atlasのPMA/straight alpha、ページのfilter/wrap、回転region、複数ページを尊重する。PMA解除・sRGB変換・再PMAの順序を定義し、暗い縁や二重のalpha乗算を防ぐ。
- 中間色は既存と同じ線形sRGB/rgba16Float。alphaとadditive発光のRGBを失わないシェーダー/ブレンド式を検証する。
- normal/additive/multiply/screenはモデル内の描画順へ適用する。外側の下段画像へ直接multiply/screenする仕様にはしない。孤立した透過素材としての合成なので、ゲーム背景へ直接描いた結果と異なる場合があることを明記する。
- Spine Y上向き座標を素材矩形内へ正規化し、共通の位置/回転へ接続する。フレームごとのboundsで自動リサイズしない。
- 基準矩形はロードしたセットアップポーズの実表示boundsを固定保存する。空ならエクスポートbounds、どちらも無効なら読込拒否。初期は映像へ収まる倍率で配置する。
- アニメーションで基準矩形からはみ出した頂点は切らない。現在の描画boundsまで中間領域を拡張し、原点オフセットを共通変形へ伝える。中心/倍率は固定基準矩形に依存させ、動きで位置がぶれないようにする。過大な領域は予算超過としてエラーにする。
- キャッシュキーはasset revision、clip ID、設定、評価ステップ/時刻、viewport/出力倍率を含む。動的フレームを素材IDだけで再利用しない。
- GPU完了まで描画パケット、atlasテクスチャ、中間ターゲットを保持する。現在の1フレームin flightの所有規則を保つ。

## 8. UI・保存・履歴

「画像・演出」でSpine選択時に、素材名、アニメーション一覧、スキン一覧、ループ、物理演算、素材開始（秒）、再生速度（倍）を表示する。クリップ名は素材名＋アニメーション名とする。静止画/動画の無関係な欄は表示しない。

全数値欄はDragValueFieldを利用し、ダブルクリック入力・左右/上下ドラッグ・Shift精密操作・中ボタン初期化・Esc取消を共通化する。ドラッグ中は仮モデルだけをプレビューし、mouseUpで1回履歴登録・保存。物理再計算の連打は集約する。初期値は素材開始0秒、速度1倍。

選択変更はシークしない。設定確定・トリム・削除・素材変更は既存EditHistoryと自動保存へ接続する。コピー/貼り付けはskeletonとatlasの絶対参照と再生設定を持ち、クリップ/キーには新IDを発行する。Undo後もrevisionと設定を照合して古い非同期結果を捨てる。外部ファイル内容自体はUndoで復元しない。

## 9. 再生と出力の準備

主音声の開始前に有効Spineクリップをロード・評価する。通常tick/停止/シークとも要求時刻を共有する。世代はプロジェクト/素材/編集/シークを区別し、古い結果を採用しない。遅延時の停止・警告は既存動画の再生準備へ統合する。

出力は専用VisualFrameProvider/SpinePoseProviderを持ち、n/30秒ごとに同じ評価・描画を使う。描画完了を待ち全フレームを書き込む。使用中の全モデル、依存ページ、選択アニメーション/スキンを事前検証し、内容と設定をメモリへ固定する。出力中のファイル変更は混ぜない。予算不足で固定できない場合は開始前に停止する。取消はファイル読込・ポーズ再計算・フレーム間へ伝播する。既存ファイルを保つ一時出力/確定経路を共有する。

| 保存 | version判定、参照の往復、Undo/Redo、コピー/複製、素材置換の全件検証、欠損復旧 |
| 出力 | 主音声のみ、全PTS/曲末、プレビューとのピクセル比較、外部更新時の内容固定、取消/失敗時に既存ファイル保持 |
| 性能 | 各3段1080p/30fpsのCPU/GPU時間、メモリ、1分経過への物理シーク時間と取消応答。端末・モデル・頂点数を記録 |

通常素材の3段30fpsを目標とするが任意の高密度モデルで保証しない。物理ONの長時間シークは待機を許可し、実測結果を記録する。上記の機能検証・既存回帰テスト・最小ウィンドウ配置・リリースビルド・署名確認までを実装の完了条件とする。

## 12. 実装契約の詳細

以下はアプリ側の設計判断であり、ランタイムの実測済み挙動ではない。試作で成立しない場合は本体への接続前に本書を更新する。

### 12.1 型とC境界

VisualAssetKindは `still / video(duration) / spine(SpineAssetDescriptor)` とし、SpineAssetDescriptorがatlasReference・exportVersion・referenceBoundsを所有する。Spine専用のoptionalフィールドを全素材へ増やさず、不正な種別の組合せを減らす。referenceBoundsはSpine単位の有限矩形（幅・高さ>0）で、ロードスケールは1に固定する。

- SpinePlaybackはanimationName、skinName、sourceIn、speed、loop、physicsEnabledの値型。名前は完全一致で解決し、存在しない名前を保存読込で補正しない。
- VisualContentは `still / video / spine(SpinePlayback)`。既存sourceTimeは未折返し素材秒を返し、sourceEndによる尺制限はvideoだけへ適用する。Spineのポーズ参照時刻と物理ステップ番号は専用の評価要求で求める。
- 保存上のversion 8検証は、種別一致、有限値、速度0.1〜16、sourceIn≥0、矩形、共通区間・キーを検査する。ファイル依存の名前・形式検証はロード段階で行い、欠損をプロジェクトJSON破損と混同しない。

SpineBridgeの公開ヘッダーはCだけでコンパイル可能にする。アプリ独自APIの責務は次に限定し、正式な関数名は固定コミットで確定する。

| 操作 | 入出力・所有 |
| --- | --- |
| asset作成/破棄 | 検証済みskeleton/atlas bytesとページID表を入力。入力bytesは呼出中のみ借用し、必要分はbridgeが所有。asset handleはprovider内だけで使用 |
| metadata取得 | animation名/尺、skin名、ページ情報、boundsをSwift所有の値へコピー |
| instance作成/破棄 | assetを参照するclip専用状態。instanceを全破棄してからassetを破棄 |
| evaluate | 再生設定、目標時刻/固定ステップ、取消状態を入力。成功時のみ描画結果を公開 |
| packet取得/解放 | 頂点・UInt32 index・コマンド・boundsをコピー。テクスチャはポインターではなくrevision内ページID |

例外は全Cエントリで捕捉し、statusとUTF-8メッセージへ変換する。メッセージの寿命と解放方法を統一する。失敗時の出力handleはnull。Swiftへborrowed pointerを持ち越さず、C++アロケーターで作った領域はC++側で解放する。Spine公式C APIの採用範囲は固定ソースの公開ヘッダーで確認し、足りない機能だけC++アダプターへ置く。

### 12.2 時刻評価の厳密化

物理OFFの参照時刻は、D>0かつloopなら `u - floor(u/D)×D`、非loopなら `min(u,D)`、D=0なら0。物理ONの目標ステップは `floor(u×60)`、ステップ時刻は整数nから `n/60` を求める。微小deltaの累積で時刻を作らない。整数変換前に積の有限性と表現可能範囲を検査し、超過はエラーとする。

初期化は選択skinの設定・セットアップポーズ・0秒アニメーション適用・物理reset/world transformを一度行う。各固定ステップは、前ステップからアニメーションを進めて適用→skeleton時刻更新→Physics_Updateの順とする。モデルが持つ物理内部stepは変更しない。物理OFFではPhysics_Noneを使い、通常制約まで無効化しない。物理ONで毎ステップSkeletonを新規化して物理状態を消さない。ループの途中にあるphysics reset timelineも、公式ランタイムの通常更新で評価する。

非loopの終端保持中はモーションの参照をDで止め、skeletonの経過と物理を進める。例えばD=2、sourceIn=3、速度1で開始を1秒左トリムするとsourceIn=4となり、保持ポーズと4秒地点の物理状態を再現する。sourceInを2へ丸めることは禁止する。

試作では0秒、ちょうどD、D±微小値、複数周、終端後、尺0を通し、アニメーション適用の最終キー・reset timeline・sequenceが公式APIで正しく評価できるか確認する。イベントの外部通知停止と、内部timelineの評価停止を混同しない。

### 12.3 非同期状態と再生待機

要求キーはprojectGeneration・assetRevision・clipID・playback設定・目標uを持つ。描画要求はさらに編集/シーク世代とviewportを持つ。instance再利用の判定は物理設定・animation・skin・revisionと現在ステップで行い、外側の変形変更だけで0秒からの物理再計算を要求しない。

状態はidle→loading→evaluating→ready、失敗はfailed、取消はidleへ戻る。計算は専用直列ワーカーで行い、main actorを占有しない。Swift actor内の長い同期C呼出しに取消を任せず、物理更新を最大120ステップの単位へ分け、各単位間に取消と新要求を確認する。1ステップが重い素材の取消遅延も性能試験へ記録する。

- 停止中のシーク: 最新要求だけ採用し、待機中の画面には準備表示を付ける。以前の画面を新時刻の正しい結果として扱わない。
- 再生開始: 現在位置の全有効素材がreadyになってから音声を開始。
- 再生中の準備遅れ: 音声を停止して実停止時刻を取得し、その時刻を全段で再評価する。準備完了時に再生意図と世代が一致していれば同じ位置から再開する。
- 待機中の停止/別シーク/プロジェクト切替: 再生意図を取消し、旧要求の完了から自動再開しない。failedでは停止を保ち、対象素材と復旧操作を表示する。

### 12.4 描画矩形・色とメモリ

固定基準矩形Bの中心を素材の原点とする。Spine点(x,y)は素材座標 `(x-B.midX, B.midY-y)` へ変換し、共通の拡大率・回転・位置を適用する。動的boundsが変わってもBを変えない。中間テクスチャの左上とB中心との差を保持し、既存の「テクスチャ中心=素材中心」という前提をSpine入力で使わない。skin変更でもBは維持し、素材置換時は新Bを採用する。置換は寸法変更によって見た目が変わる可能性をUIに示す。

PMAページはsRGB符号値のPMAを解除してから線形化し、straightページはそのまま線形化する。その後tint/tint blackとalphaを適用し、線形PMAとして中間面へ描く。alpha=0での除算は行わない。PMA画像をsRGBテクスチャの自動変換だけで読んでからPMA解除する順序にはしない。公式rendererの色表現との対応・フィルター境界は試作の画像比較で確定する。

中間面のnormalはPMAのsource-over。additiveはRGBを加算し背景alphaを維持する方式を候補とし、multiply/screenは公式描画例に対応する係数を検証する。係数とalphaの最終表、tint blackの式は試作成果として必ず記録する。additiveだけでalpha=0かつRGB>0となる画素をCore Image処理で失わないか確認し、失う場合は発光面を別に保持して同じ変形後に加算する方式へ変更する。この判定が済むまで全blend対応を完了扱いにしない。

初期予算案は共有ロードデータ/展開atlasが256MiB、Spine用GPUリソース（atlasと中間面）が合計512MiB。CPU/GPU両方に保持するページは各予算へ別計上する。中間面はrgba16Floatの8byte/pxで算出し、一時面・同時使用する面も含める。ページ/面寸法はMetal対応上限と予算の両方で検証する。LRUは未使用のみを解放し、GPU実行中の面を再利用しない。予算超過を低解像度化で黙って回避しない。

atlasのページパスはsymlink解決後もatlasディレクトリ配下であることを検査する。revisionはskeleton・atlas・順序を固定したページ相対名と内容のSHA-256から構成する。出力準備では読み取った同一bytesを検証とロードへ渡し、検証後にパスから別内容を読み直さない。読込中の更新を検出した場合は準備をやり直すよう案内する。

| ゲート | 必須成果 | 不成立の場合 |
| --- | --- | --- |
| G1 ランタイム | 4.3の完全commit SHA、license、使用ソース一覧、Cヘッダー、macOS 14向けビルド | SDKの固定と境界設計を修正 |

サンプルは単一モデルですべての機能を満たすと仮定せず、機能別の公式サンプルと必要な小規模fixtureを揃える。比較は同じrevision・skin・時刻・背景・色空間で行う。頂点はSpine単位の絶対誤差1e-4＋相対誤差1e-5を初期基準とし、画像は線形RGB/alphaの差分と透過境界を確認する。MP4との比較では圧縮誤差を別に評価する。許容差変更には測定理由を残す。

G1〜G4は全体対応の判定条件。初期段階ではSPINE_PHASE1.mdに定めた部分範囲を適用する。G1〜G4の未取得結果は設計の未確定項目として残す。ユーザー操作・保存・時間・責務の設計は本書で具体化済みだが、製品として実装完了・性能保証された状態ではない。
