# 電撃ビーム

2026-11-20実装。指定シェーダーの電撃表現を参考に、以下の操作・範囲・初期値を採用した。

## 参照と採用範囲

[Anime background / mmerchante](https://www.shadertoy.com/view/wsjGRw)（2019-01-26）のImageコードをブラウザーで確認した。元作品は電撃とアニメ風の流線背景の組み合わせ。

- 電撃は折れ線の区間距離と太さから芯・広い光を生成する。準乱数列で節点をずらし、6回のMagic呼出しで束を重ねる。各呼出しは22区間を評価する。
- 背景はiChannel0のテクスチャを流し、黄橙と反転色を周期的に切り替える。iChannel1は電撃の座標を歪めるノイズに使う。
- iTimeを24段階/秒へ量子化する一方、形状・移動はiFrameにも依存する。再生fpsが違うと一致しない。
- 0.5〜12秒の固定導入、画面全体の揺れ、独自のRythm周期を持つ。逆順smoothstepも使う。

「電撃ビーム」は電撃の芯と光を独立した生成ノードにする。流線背景・反転配色・固定導入は内蔵しない。必要なら単色背景や直線効果線、シェイク、色調補正を別ノードで組み合わせる。初期状態から表示し、出現・消失は明るさのキーや音楽同期で編集できるようにする。元作品の完全再現モードは初期範囲外。

外部テクスチャ・音楽を同梱せず、ノイズは固定seedの手続き生成へ置換する。実装は独自の節点生成・ハッシュノイズ・距離描画で、原作のソース・テクスチャ・音楽は転用・同梱しない。参照元は上記リンクへ記録する。

## 配置と操作

「演出を追加 → 効果線 → 電撃ビーム」。EffectKind.electricBeamとImageEffects.ElectricBeamを追加する。画像・動画・Spine・空クリップで共用し、同種は1クリップ1ノード。前段へ電撃を加算し、後段の加工に渡す。別レイヤー、歌詞、スペクトラムは読まない。

空クリップに追加すれば電撃だけのレイヤーとして使える。空クリップの既定の単色背景をOFFにすると背面が透けることを説明する。追加時に背景設定を勝手に変更しない。

位置は1080p左上原点の中心X/Y、方向は右向き0°・時計回り正、長さは中心から両端までの総延長。基本素材の位置・回転には追従せず画面基準で配置する。前段シェイクは電撃に作用せず、後段シェイクは素材と電撃を一緒に揺らす。

| 項目 | 範囲 | 初期値 | 意味 |
| --- | --- | --- | --- |
| 中心X / Y | −1920〜3840 / −1080〜2160px | 960 / 540px | 束の中心 |
| 角度 | −180〜180° | −30° | 右上へ伸びる方向 |
| 長さ | 1〜7680px | 2400px | 電撃の生成区間 |
| 束の幅 | 0〜1080px | 180px | 複数の軌道の中心分布幅 |
| 本数 | 1〜6 | 6 | 重ねる軌道数 |
| 太さ | 0.5〜40px | 3px | 芯の全幅 |
| 折れ曲がり | 0〜400px | 90px | 各軌道の法線方向変位の上限 |
| 光の広がり | 0〜300px | 48px | 芯の外側に広がる光の半径 |
| 明るさ | 0〜400% | 100% | 芯と光の共通倍率 |
| 動きの速さ | 0〜400% | 100% | 流れ・形状更新の時間倍率 |
| 色 | RGB | 水色 (0.20, 0.75, 1.00) | 光の色。芯は白へ寄せる |

全数値をDragValueFieldと共通の手動キー・項目別音楽同期へ接続する。本数は評価後に整数へ丸める。色は固定設定、初期状態はキー・同期なし。「配置を変更」でseedを再抽選しUndo1回。更新頻度は初期版では固定24Hzとし、数値項目を増やさない。太さ0.5px刻み、他のpx項目は1px刻み、角度は1°刻みを採用する。

中心X/YをPreviewPositionPairへ登録し、既存プレビューハンドルで編集する。ドラッグ中は仮描画、mouseUpで1回確定、Esc取消。ダブルクリック入力・中クリック初期化・方向固定ドラッグ・Shift微調整を共有する。通常の基準値編集と同様にキー・範囲も移動し、キーを自動追加しない。

## 時計と決定性

localTime = 曲時刻 − clip.start、t = (localTime + phaseOffset) × speed / 100。形状の仮想コマ番号はfloor(t × 24)。iFrame、実際の描画回数、壁時計、乱数呼出しの順序には依存しない。

全軌道をseed・軌道番号・仮想コマ番号・節点番号から評価する。全形状は24Hzで切り替え、同一コマ内は静止する。元コードのiFrame/12・/24をそのまま使わず、初期版ではこの一つの時計へ統一する。速度0はt=0で静止し、電撃を消さない。負時刻もfloorと正の剰余を定義して決定的に扱う。

左トリムでphaseOffsetへ開始位置の差を加算する。同じ曲時刻の形状を維持する。通常移動・複製はクリップ相対のアニメーションを保ち、並べ替え・OFF/ONで時計やseedをリセットしない。速度のキー・同期は既存演出と同じ時刻への乗算で、積分はしない。速度変化による位相ジャンプは許容する。

## 生成とGPU処理

ElectricBeamGeometryでフレームごとの折れ線と区間インスタンスを生成し、専用Metal vertex/fragmentで描く。全画素で6×22区間を反復する元の構成は避ける。最大6軌道×64区間の上限を固定し、プレビューと出力で同じ幾何を使う。

1. 方向と法線の局所座標を作り、束の幅に従って軌道の法線オフセットを固定準乱数で配分する。
2. 区間数をclamp(ceil(長さ/120px), 8, 64)で決める。節点を等間隔に置き、上限付きの変位と連続ノイズで折り曲げる。両端の変位は0へ減衰する。
3. 仮想コマから循環するノイズ位相を求め、節点に沿って形状が流れる印象を作る。seedと軌道番号で変位・太さを変えるが、固定の強制点滅は加えない。
4. 各区間のquadを芯半幅＋光半径＋AA分だけ広げる。fragmentで最近点への距離と軌道上の距離を取り、端の丸み・芯・有限半径の光を評価する。ゼロ長区間は描画しない。
5. 区間の継ぎ目で光量が二重にならないよう、軌道ごとに一時面をクリアして成分ごとのmaxブレンドでunionし、完成した軌道を加算する。一時面は6枚常駐させず1枚を再利用する。軌道同士の重なりは光量加算する。

芯の色は指定色から白へ75%寄せ、光は指定色。距離AAは出力解像度を反映し、細い芯が低解像度プレビューで消えないよう面積相当を保つ。光は半径で厳密に0となる滑らかな減衰、芯も有限幅にする。光の広がり0は芯だけ。明るさ0は描画を省略して入力をそのまま渡す。元の逆順smoothstepは1−smoothstepによる明示的な式へ置換する。

線形RGBで電撃光を加算し、中間面のalphaは変更しない。黒い全画面面やalpha1の背景を作らない。指定色はsRGBから線形へ変換する。HDR光量を途中でSDRへ制限せず、クリップ共通不透明度はチェーン完成後に一度だけ適用する。後段の色補正・2値化・ブルーム・マスクがalpha0の光も扱える既存契約を使う。

生成座標は余白を除いた1080p画面座標で評価し、Core Image方向へ反転してチェーンへ合流する。電撃自体は入力をサンプルしないため入力supportは0。既存のチェーン中間面の余白領域にも、範囲が交差する電撃を描く。画面内だけの別面に一度切り落とす構成は採用しない。後段ブラー・シェイク等のsupportは既存集計へ従い、最終映像枠で切る。

## モデルと接続

payloadはisEnabled、centerX/Y、angle、length、spread、count、width、bend、glowRadius、brightness、speed、color、seed、phaseOffsetを持つ。全数値のfinite/範囲、RGB、seedを検証する。曲線・同期・表示範囲はEffectNodeの既存領域へ保持し、ノードID＋ImageParameterで参照する。EffectKindの既存整数値を動かさず末尾へ追加する。

| 箇所 | 変更 |
| --- | --- |
| ImageEffects / EffectChain | payload、初期値、検証、投影、左トリム時計、追加削除 |
| ImageAnimation / EffectAutomation | 数値項目、物理範囲、読書き、共通評価、削除対象 |
| EffectCategory / ImageEffectsEditor | 効果線メニュー、詳細欄、色、seed変更 |
| PreviewPositionPair | 中心XYの選択と操作 |
| ElectricBeamGeometry（新規） | 決定的な節点・区間生成、境界、CPU参照評価 |
| MetalSceneRenderer / Scene.metal | インスタンス描画、軌道union、余白、加算、バッファ再利用 |
| ProjectMigrator / ProjectFile | 次版への移行と読込境界 |
| 関連テスト・仕様 | 保存、Undo、クリップコピー、描画、MP4の受入試験 |

評価済み全設定、tの仮想コマ、seed、ノード順、解像度を描画キャッシュへ含める。幾何キャッシュには形状へ作用する設定だけを使い、色や明るさだけの変更で節点を作り直さない。素材取得・VisualFrameProviderに外部素材依存は追加しない。

保存はv20・読込v17〜20。v15→16は既存ノードを保持し、電撃を自動追加しない。v15以前にelectricBeamが混入していれば拒否する。対応範囲外のv12→13変換器は削除した。未知payloadを黙って捨てず、バックアップ・atomic保存・読込失敗時の原本保護を既存ProjectStorageと共有する。

削除は専用キー・同期・表示範囲を除去する。コピー/複製はノードとキーIDを再発行するがseedと位相は保持する。追加/削除/色/seed変更/有効切替/並べ替えは既存の確定・自動保存・Undo経路を使う。

## 実装構成と検証

1. 原文を転用せず独自実装し、参考作品のリンクを保持する。
2. モデルとCPU幾何を実装し、範囲・極値・同時刻の決定性・速度0・負時刻・左トリム・コピーを検証する。
3. 透明面上のMetal描画とチェーン接続。斜線・水平・垂直・短い線・最大長・太さ最小最大・幅0・光0・端のunion・余白を確認する。
4. UI、自動化、音楽同期、ハンドル、保存移行、履歴を接続。整理フェーズで時計・数値定義・描画責務の重複と不要なコードを見直す。
5. 共通描画とMP4、既存演出の回帰を実行。最終コードで./scripts/build-app.shを成功させる。

受入条件:

- 初回から電撃が見え、長いクリップでも固定導入や12秒で切れない。速度0でも表示される。
- 透明電撃を画像・動画・Spineへ重ね、素材のalphaを壊さず背面が透ける。不透明度0・ノードOFF・全体バイパスは無作用。
- 電撃→ブラー/色補正/マスクと逆順で意図した違いが出る。後段ブルームが電撃の光を抽出できる。
- 同時刻へランダム順にシークして一致する。30fps出力とプレビューの共通時刻で仮想コマが一致し、停止中にも揺れない。
- 操作取消、Undo/Redo、保存往復、コピー、移動、左トリム、範囲外キー、同期のみレーンを確認する。
- GPU上のNaN/Inf、縮退区間、継ぎ目の光量突出、上下反転、画面端の光の欠けを試験する。
- 1080p・1ノード最大値と3段最大値、可変レイヤーでの増加を計測する。GPU時間・一時面ピークメモリ・シーク後再評価を記録し、目標33.3ms/フレームとの差を報告する。未計測の性能保証は置かず、プレビューだけ形状を減らす最適化は行わない。

## 検証結果

専用8件（時計/幾何/検証/自動化/保存/描画/透明加算/継ぎ目/画面外ぼかし/UI/履歴/複製/削除/HDR・alphaのCPU参照比較/MP4）を含む整理後の関連38件成功。整理前の全体266件は外部Spineサンプル1件スキップ、失敗0。手動GUIでの実素材操作は未実施。

1080p最大設定の1/3/10段はGPU最大10.79/22.87/74.46ms。最小対象Macや多数段の実時間再生は非保証。追加の一時面は余白なし1080pで約15.8MiBを1枚、幾何バッファは最大50設定×384区間×32byteで約0.59MiB（ドライバーの追加領域を除く）。プロセス累積ピークRSS約237MBはGPU専用メモリ量ではない。形状をプレビューだけ減らす処理は使わない。
