# 同一レイヤーのクリップ・クロスフェード

作成日: 2026-11-22 JST。更新日: 2026-11-23 JST。状態: **実装済み**。

同一レイヤーの順方向2クリップの重なりをクロスフェードとして配置・描画・編集する。

## 1. 要件と提案の範囲

ユーザー指定の要件:

- 同じレイヤーでクリップを重ねるとクロスフェードする。
- 基本は透過値によるブレンドとし、重なった時間がそのままクロスフェード時間になる。
- 重なり区間に、添付画像のように交差する2本の曲線を描き、クロスフェード中と分かるようにする。

以下は実装した曲線形状、重複制約、操作、保存方式。対象は「クリップ」タブの画像・動画・Spine・空クリップとその組合せ。歌詞と主音声は対象外。動画素材内の音声も使用しない。

## 2. 配置ルール

開始順にA、Bとしたとき、`A.start < B.start < A.end < B.end` を満たす重なりを許可する。AからBへ切り替わる区間は `[B.start, A.end)`、長さは `A.end − B.start` 秒。切替専用クリップや固定のフェード時間は作らない。

| 配置例 | 結果 |
| --- | --- |
| A=0〜5秒、B=4〜9秒 | 4〜5秒の1秒間で切替 |
| Bを3秒開始へ、長さを維持して移動 | 3〜5秒の2秒間へ延長 |
| Bの開始がAの終了と一致 | 通常のカット切替。曲線なし |
| AとBの間に空白 | 空白を維持。自動接続しない |
| 別レイヤー同士の重なり | 従来の段順合成 |

以下を拒否する。

- 同じ時刻に3クリップ以上が有効になる配置。
- 完全包含、同一開始、同一終了、同一区間。順方向のA→Bが一意にならない重なり。
- 曲外配置、クリップの最小長1/30秒未満、動画素材の使用尺超過など既存の不正区間。

A→B→Cの連続クロスフェードは許可する。ただし `A.end <= C.start` が必要。Bのフェードインとフェードアウトは接してよいが重ならない。区間は開始を含み終了を含まない。

重なりは正の長さなら許可し、独自の最小クロスフェード時間へ補正しない。1/30秒未満では30fps出力に混合フレームが現れない場合がある。既存のスナップと入力精度を維持し、描画のために時刻を丸めない。

## 3. 曲線と不透明度の評価

初期曲線は、添付例に近い端がなだらかな対称S字とする。区間内の進行率と混合率を次で定義する。

```text
u = clamp((time − B.start) / (A.end − B.start), 0, 1)
f = u² × (3 − 2u)                 // smoothstep
Aの混合率 = 1 − f
Bの混合率 = f
```

開始でA=100%/B=0%、中央で50%/50%、終了でA=0%/B=100%。合計は常に100%。曲線編集、補間種類の選択、独立した長さ欄は初期仕様には含めない。

各クリップの固定不透明度・キー・LFO・音楽同期は既存のParameterEvaluatorで評価し、その後にクロスフェード係数を適用する。設定値や既存の不透明度カーブを自動変更・生成しない。タイムラインの交差線は純粋なクロスフェード混合率を表し、元素材のalphaや不透明度自動化は含めない。

## 4. 映像の合成

各クリップの素材取得・変形・演出チェーン・自クリップマスク・共通不透明度までを個別に評価する。その完成面を同じ画面座標の透明な中間面へ揃える。

線形sRGBのpremultiplied RGBAで、A/Bの完成値をそれぞれ `P_A` / `P_B` として、レイヤー完成面を次で求める。

```text
P_layer = (1 − f) × P_A + f × P_B
```

この面を下のレイヤーへ1回だけsource-over合成する。2枚を半透明にして順次source-overで重ねる方法は採用しない。両方が不透明なら混合中もalpha=1を保ち、中央で背景が余計に透けることを防ぐ。

半透明PNGや変形後の素材外は本来のalphaのまま混合する。意図した透過部分では下段が見える。加算光はalpha=0のRGBも混合し、失わない。空クリップの演出・背景・粒子・ブルームも完成面に含め、まとめて切り替える。歌詞・スペクトラムはレイヤー合成後に従来どおり描画する。

プレビューとMP4で同じ評価器・合成式を使用する。動画2本や動画＋Spineでも、同じ曲時刻で両方を評価する。素材時計・再生速度・ループ・トリムの位相ルールは各クリップに従う。

### 直下段マスク

直下固定段の「クロスフェード済み完成面」を対象とし、空段を飛ばさない。マスク所有段も2クリップ混合中になり得るため、先頭1クリップを選ぶ実装は廃止する。

各所有クリップのマスク透過係数を画素ごとに `T_A` / `T_B` とする。既存のマスク強さと所有クリップの評価済み不透明度を反映し、マスク無効・未設定・不透明度0は係数1（無作用）とする。所有段のクロスフェード中は `T = (1−f)T_A + fT_B` とし、直下段完成面のRGBAへ1回掛ける。ここでの所有不透明度にはクロスフェード係数を二重に掛けない。マスク解除側へ移る場合も連続的に解除する。所有段が空・非表示なら無作用。

## 5. タイムライン表示と対象選択

- 同一行の重なり区間だけに薄い背景と2本の明るい曲線を重ねる。Aは左上→右下、Bは左下→右上。上端=100%、下端=0%、区間中央で交差する。
- 同じsmoothstep評価から線を描き、実際の混合率と一致させる。表示領域外を切る場合も、見えている区間を0〜100%へ引き伸ばさない。
- 曲線はクリップ背景・サムネイルの前面、文字・端の操作表示・再生ヘッドの背面。元のクリップ色と選択枠を残し、重なりの左右境界を表示する。
- 幅と高さが足りる場合は「クロスフェード 1.00秒」を表示し、狭い場合は文字を省略。極小幅でも重なり位置の印を残す。ホバーのツールチップで両クリップ名と正確な長さを確認できる。
- 行を低くしても交差線を残す。時間ラベルなど既存の省略ルールは維持する。

曲線は状態表示として扱い、独立の選択・ドラッグハンドルにはしない。重なり区間の本体クリックは中央より左をA、中央以降をBへ割り当てる。右クリックも同じ判定を使う。選択時にシークしない。

端トリム判定は本体判定より優先する。両端のヒット領域が競合するほど狭い場合は選択中クリップの端、次に距離が近い端、同距離ならBの開始端を優先する。ホバー表示とmouseDownは同じ判定を使う。曲線を描く領域でも同じルールとし、透明な上側クリップ矩形が下側への操作を奪わないようにする。

オートメーションは選択クリップの対象を編集する。重なりがあっても他方のキーを同時編集しない。クリップ本体選択で制御点選択を解除する既存ルールを維持する。

## 6. 作成・編集・取消

移動、左右端トリム、時刻入力、別段への移動、貼り付け、複製、素材ドロップ、新規作成、動画速度変更の全経路へ同じ配置検証を適用する。現在の「既存クリップ上なので拒否」は、全体の配置候補が第2節を満たすかの判定へ置き換える。ドロップを素材置換とは扱わない。

- ドラッグ中は仮モデルで区間・曲線・プレビューを更新し、mouseUpで1操作として履歴登録・自動保存する。
- Esc・終了準備で元へ戻す。不正候補は警告色で表示し、プレビューは最後の有効候補を保持、無効位置でmouseUpしたらドラッグ開始前へ戻す。
- 不正な数値入力は全体を反映せず、理由を表示する。「3クリップが同時に重なります」など、単なる衝突と区別する。
- 重なりを離すと自動解除する。クリップ削除時は残ったクリップを元の不透明度で描き、既存キーは変えない。クロスフェードだけのDelete操作は設けない。
- ロック・非表示・段の並べ替えの既存ルールを維持する。非表示でも配置検証し、ロック段へ配置・移動しない。

数値を編集する場合は既存の開始/終了のDragValueFieldを使う。クロスフェード長は算出表示のみであり、新しい編集数値欄を増やさない。

## 7. モデル・保存・実装境界

クロスフェードはクリップ区間から導出する。ペアID、長さ、係数、表示曲線をJSONへ重複保存しない。`LayerCrossfade`などの派生値にA/BのID・開始・終了と混合率評価をまとめ、配置検証・タイムライン・レンダラーで共有する。

意味上の保存仕様が変わるため、ProjectFileはv21。読込境界は現行＋直前3世代のv18〜21とする。v18〜20の重なりなし配置は時刻・演出を変更せず移行し、既存方針どおりバックアップして保存する。v17以前・未来・不明形式は対応外。旧形式の不正な重複を正規のクロスフェードとして救済せず、その版の検証後に移行する。

主な影響範囲:

| 対象 | 必要な変更 |
| --- | --- |
| VisualTrackと編集経路 | 重複禁止を順方向ペア検証へ変更、派生区間と全有効クリップの取得 |
| TimelineView / VisualEditor | 交差線・ラベル・統一ヒット判定・全配置操作の仮変更と確定 |
| 各素材provider / VisualFrameProvider | 同一段で2ソースを保持し、片方だけを選ばない |
| PreviewFrameReuse / Appのプレビュー更新 | 両ソースの揃った最新revisionを一括表示。片側だけ新しい状態を出さない |
| MetalSceneRenderer / Scene.metal | クリップ完成面→ペア混合→段間マスク→段合成。段IDとクリップIDのキャッシュ責務を分離 |
| ProjectFile / ProjectMigrator / EditHistory | v21境界・旧版検証・往復・配置変更のUndo/Redo |
| 関連仕様 / README / AGENTS | 重複禁止・単一有効クリップ・段間マスク・保存境界の記述を実装後に更新 |

加工済み面は既存のクリップキャッシュを活用し、混合率の変化だけで演出チェーンを再生成しない。追加面は重複または段間マスクのある区間だけで使い、全段で1枚を順次再利用する。GPU完了まで両動画バッファとSpine描画結果を保持する。欠損素材・出力取消・キャッシュ予算の既存方針を守り、出力時に片側欠損を無視しない。

## 8. 検証条件

受入条件:

1. 1秒/2秒の重なり、接点/空白、A→B→C、包含/同端点/3重の拒否を全編集経路で確認する。
2. 曲線と実混合率が開始/中央/終端で一致し、ズーム・横スクロール・低い行でも正しく表示される。
3. 同じ不透明画像2枚のクロスフェードで中央が暗くならず背景も透けない。半透明素材・異なる変形・不透明度キー/LFO/同期・alpha0加算光を画素比較する。
4. 画像/動画/Spine/空クリップの組合せ、同一動画素材の異なるsourceIn、両動画の速度変更・左トリム・シーク・逆方向シークを確認する。
5. 直下段マスクの片側有効/両側有効/不透明度0/非表示/空段を確認する。混合率を二重適用しない。
6. 重なり内のA/B選択・端トリム・右クリック・キー編集が判定どおり動く。ドラッグ取消・無効位置での確定・Undo/Redoで区間と表示が一致する。
7. v21保存往復、v18〜20移行、旧形式の重複拒否、読込失敗時の上書き防止、コピー/複製後のIDと派生ペアを検証する。
8. 同時に2本をデコードするMP4でプレビューとの時刻・画素比較を行う。50段の配置検証と代表的な複数重複段のGPU時間・追加メモリを測り、1本時の回帰と資源上限を確認する。
9. 重複判定・係数・選択判定の重複と責務を整理した後、関連試験と `./scripts/build-app.sh` を成功させる。

## 実装と検証記録

`LayerCrossfade`が区間・係数を共有し、`VisualTrack.active`は同段の両クリップを返す。`MetalSceneRenderer.compose`はクリップ完成面を加重加算し、マスク係数を混合して段単位で合成する。TimelineViewは交差線・区間名/時間のツールチップと共通選択判定を使う。

CrossfadeTestsの11件と関連試験62件で配置・画素・マスク・プレビュー再利用・4種類の素材混在・タイムライン操作・独立した動画時計・2動画を含むMP4全12フレームを検証。50段100有効クリップの検証と3段同時混合も確認。長時間・50段同時描画の性能と実ユーザーSpineモデルでの組合せは未計測。最終の整理後試験・ビルド結果はPROGRESS.mdへ記録する。
