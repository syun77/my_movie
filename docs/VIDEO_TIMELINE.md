# 動画素材のタイムライン配置と同期再生の設計

作成日: 2026-11-11。同期再生と、動画配置を含むMP4出力を実装済み。ユーザーの確定要件は「画像・演出のタイムラインへ動画を配置できること」「主音声と時間を同期して再生すること」「動画内の音声は再生不要」、および「動画配置ありのMP4出力」。以下の操作・初期値・段階分けは設計上の提案。

## 1. 採用方針と最小範囲

AVFoundationを利用する。すでにAVAudioPlayerによる主音声再生、音声解析、AVAssetReader／AVAssetWriterによる出力に導入済みであり、新たな外部ライブラリは不要。最低macOS 14を維持する。

最初はローカルのMP4／MOVの映像を0.1〜16倍速・順方向で再生する。コンテナの拡張子だけで対応を判断せず、映像トラックの読込・実デコードを検証する。SDRのH.264／HEVCを優先検証対象とし、HDR・透過動画・保護された素材・ネットワークURLは初期対象外とする。未対応素材は読み込み前に理由を示す。

画像と動画を同じ3段に混在可能にし、同段の重なり禁止・別段の重なり許可・既存の合成順を維持する。主音声の長さを作品長とする。配置・移動・両端トリム、停止画表示、シーク、保存・復元、Undo/Redoを最小範囲に含める。ループ、逆再生、動画音声のミックス、プロキシ生成、連続サムネイルは後続機能とする。

動画の初期設定は自動アニメOFF。既存の固定変形・手動キー・演出は共通描画へ接続して利用する。動画を別のAVPlayerLayerとして重ねず、歌詞・スペクトラム・画像と同じMetal合成に参加させる。

## 3. データモデルと時刻の定義

共通モデルはVisualAsset（id、reference、kind）、VisualTrack（assets、3段のlayers）、VisualClip（id、assetID、start、end、content、変形・キー・演出）とする。contentはstill／video(sourceIn, speed)の関連値付きenumとし、静止画へ無意味な動画設定を持たせない。参照先のkindとcontentの一致を検証する。プレイヤー、デコーダー、バッファ、読込状態は永続モデルに含めない。

動画メタデータは実ファイルから非同期取得する。対象映像トラックの有効timeRange、preferredTransform、サイズ、色特性、可変フレームレートを確認する。初期版は複数映像トラックから再生可能な先頭トラックを選び、その選択規則を固定する。実装時は対象SDKの非同期load APIを利用する。

プロジェクト時刻をt、配置開始をs、素材開始をiとすると、映像の参照時刻は次の通り。

```
clip active: start <= t && t < end
sourceLocalTime = sourceIn + (t - start) * speed
trackTime = videoTrack.timeRange.start + sourceLocalTime
0 <= sourceIn
sourceIn + (end - start) * speed <= videoTrack.timeRange.duration
```

sourceInは「選択した映像トラックの有効範囲先頭からの秒数」。映像トラックの開始PTSが0でない素材もこの変換で扱う。音声トラックやコンテナ全体のdurationを動画の使用可能長として代用しない。保存は既存モデルに合わせ有限のDouble秒、AVFoundation境界ではCMTimeへ変換する。30fpsやnominalFrameRateから素材フレーム番号を計算せず、デコードされたPTSと表示区間で選ぶ。出力の30fpsと素材のfpsを分離する。

例: 配置開始10秒、sourceIn=3秒なら、曲の12秒で素材の5秒を表示する。配置を20秒へ移動してもsourceIn=3秒を保ち、曲の22秒で同じフレームを表示する。

## 4. 配置・トリム・素材操作

- 動画追加は指定段・スナップした開始位置から、素材残長／次のクリップ開始／曲末の最小値まで。終了はその上限を超えないグリッド点とし、最小長は既存の1/30秒。合法な区間が作れなければ配置しない。素材尺を超えて拡張・ループ・静止保持しない。
- 本体移動と段移動はsourceInと長さを保持。左端トリムは開始の差Δ×speedをsourceInへ加算し、終端と表示内容の対応を保つ。右端トリムはsourceInを維持する。
- 左へ延ばす場合はsourceIn >= 0、右へ延ばす場合は素材終端を上限とする。スナップより素材境界・非重複の制約を優先し、合法なスナップ点がなければ元へ戻す。
- 開始時刻欄は長さとsourceInを保つ移動。終了欄は右端トリム。「素材開始」欄は配置区間を保って参照区間のみ変更し、素材終端超過は拒否する。
- 左トリムは既存の手動キー・演出位相補正とsourceIn変更を同じモデル操作で行い、二重補正を避ける。ドラッグは仮表示、mouseUpで一度確定、Escで取消。
- 数値欄はDragValueField。ダブルクリック入力、上下左右ドラッグ、中ボタンで初期値へ戻す。「素材開始」の初期値は0秒。時刻スナップは配置時刻に適用し、素材開始は元動画の秒位置を直接指定する。
- コピー／貼付／複製はsourceInを保持し、クリップ・キーIDを再発行する。動画の専用アイコン、ファイル名、区間を表示し、タイムラインの全フレームサムネイルは作らない。
- 管理画面を「素材管理」へ一般化。使用中の動画置換は全配置の参照範囲を事前検証し、短い素材への置換を部分適用しない。種別の異なる置換は初期版では禁止。欠損素材は参照・配置を保持し、復旧可能にする。

## 5. 同期とデコード方式

### 比較と採用案

| 方式 | 評価 |
| --- | --- |
| AVPlayer + AVPlayerItemVideoOutputを動画ごとに設置 | 再生向けの先読みが使えるが、AVAudioPlayerと独立した時計を持つ。開始・停止・シーク・バッファ待ち・複数動画の同期補正が必要 |
| 主音声と動画をAVComposition／AVPlayerへ統合 | 単一の再生時計を構成可能。音声基盤の変更と、編集ごとのcomposition更新・複数レイヤーのMetal合成への取り出し方の設計が必要 |
| AVAssetReaderで主音声時刻に対応する映像を取得 | 独立した動画時計を持たず、既存の音声基盤とMetalに接続できる。ランダムシークと先読み性能を実機で確認する必要がある |

初期版はAVAssetReader + AVAssetReaderTrackOutputによる時刻指定取得を採用する。H.264/VFR・HEVC・3段1080pと実再生の技術テストで確認した。動画トラックの出力だけをreaderに追加するため、素材内の音声を再生しない。AVAssetImageGeneratorは素材一覧の代表画像用に限定し、毎フレームの再生には用いない。

これは厳密なハードウェア同期を保証する方式ではない。音声時刻を参照するため累積する速度差を避けられるが、デコード・画面更新・音声デバイスの遅延は別に残る。表示の測定結果で採否を判断する。

### 取得手順と負荷制御

VideoFrameProviderはクリップ単位のセッションを持つ。同じ素材を別の素材位置で使う2クリップは別セッションとする。actor／専用直列実行環境でreaderを所有し、MainActorではデコードしない。

1. 再生前に有効クリップの最初のフレームと短い先読みを準備する。主音声を開始した後はAVAudioPlayer.currentTimeを唯一の基準にする。Timerの呼出回数や前回時刻への加算で進めない。
2. 順方向ではreaderを継続し、現在フレームと次フレームのPTSから、要求時刻を含む表示区間のフレームを返す。可変fpsも同じ規則とする。最終サンプルは有効トラック範囲内でのみ保持する。
3. 後方シーク・1秒超の前方ジャンプはreaderを再構築する。要求時刻の1秒前から読み、PTSで選択する。必要な直前サンプルを得られない場合はトラック先頭から読み直す。GOP境界のデコード処理はAVFoundationへ委ねる。
4. 操作連打は最新要求へ集約。セッション単位で処理中1件＋最新待機1件とし、無制限にTaskを作らない。世代番号をプロジェクト／素材／編集・シークに付け、古い結果を表示しない。通常再生tickでは世代を更新せず、取得完了時に最新時刻を確認して陳腐化したフレームを捨てる。
5. 停止・シーク直後は指定時刻のフレームを要求する。準備中は状態表示し、別クリップやシーク前の画像を新しい時刻の映像として表示しない。再生中の一時的遅延では同じクリップの直前フレームだけ保持し、音声を基準に遅れたフレームを間引く。要求時刻から250ms超遅れた場合は主音声も停止して警告する。
6. 各フレームは映像・歌詞・スペクトラム・変形を共通の要求時刻で評価したRenderSnapshotにまとめる。時刻と古い画像の非同期の組合せを避ける。次回要求は描画完了を待たず最新値へ集約できるようにする。

動画セッションは現在＋次の2フレーム、最大3セッションを保持する。保持バッファの合計が128MiBを超えた場合はセッションを解放して警告する。GPU使用中の保持とデコーダー内部メモリは別途必要。次クリップの先読みはまだ行わない。画面外・プロジェクト切替・終了で解放する。

Transportは再生・停止・全曲シーク・タイムラインシーク・Optionホイール・曲末・読込・終了を共通処理へ集約する。再生準備中の取消も扱い、音声だけ先行して開始しない。AVAudioPlayerの自然停止時も最終時刻を明示的に更新する。

## 6. 共通描画

VisualRenderLayerの入力をstill(CGImage)／video(CVPixelBuffer, PTS, generation)へ分け、配置・アニメ・演出・段順は共有する。動画のピクセルバッファをCIImageへ変換し、既存CIContextとMetalへ渡す。毎フレームCGImageへコピーしない。初期はBGRAデコードを候補とし、色変換・メモリ帯域を測定して確定する。

preferredTransformを適用して縦動画・回転動画の表示サイズと原点を正規化してから既存の配置変形を適用する。アスペクト比・既定の収まり方は静止画に合わせる。入力の色空間／マトリクス／レンジを尊重し、既存の線形sRGB合成からプレビューsRGBへ変換する。HDRを無条件にSDRとして扱わない。

現行の素材ID中心のテクスチャ／演出キャッシュを、静止画と動的フレームで分離する。動画はフレーム識別（セッション世代＋PTS）を含め、同一素材の別時刻を取り違えない。過去フレームごとのキャッシュを蓄積せず、GPU完了までCVPixelBufferと中間リソースを保持する。

## 7. 保存・履歴とMP4出力

ProjectFileをversion 9とし、visualAssets／visualLayersと動画contentを保存する。保存・履歴・クリップボード・素材参照確認・行高さ・レーン選択の関連型を一括で更新し、画像専用モデルの互換ラッパーは残さない。既存のAssetReferenceによる相対／絶対参照を共有する。

旧形式との互換性は要求しない。初期案は既存の「バックアップして新規作成」経路を用い、旧プロジェクトを黙って上書きしない。既存version 4／5からの移行を実装する場合も読込境界一箇所だけに集約する。実ファイルのメタデータは復元時に再検証し、素材尺不足・欠損・未対応はモデルを保持して警告する。復旧操作が終わるまで不正な変更を確定しない。

MP4出力はVisualFrameProviderの専用インスタンスを使い、n/30秒ごとに画像と動画の有効クリップを取得する。動画内の参照時刻はsourceIn + (n/30 - clip.start) * speedとし、PTSに対応する映像をデコードする。画像・動画を段順に並べ、変形・演出・歌詞・スペクトラムを同じMetalSceneRendererで描画する。デコード・GPU完了を待ってすべての出力フレームを書き込み、プレビューの間引きや遅延停止は適用しない。

主音声だけを48kHz AACへ変換し、1920×1080／30fpsのH.264映像と同じMP4へ書き込む。低サンプルレート入力もAACの出力サンプルレートへ変換する。素材動画の音声トラックは読まず、主音声の長さを作品長とする。曲末の端数は既存の出力と同じく最後のフレームを次のフレーム境界まで保持し、音声は元の長さを保つ。

出力前にモデルと使用中素材の実ファイルを検証する。素材尺不足・種類不一致・欠損・読込不能はエラーにし、未配置素材は検証対象外。検証中・動画デコード中も取消を確認する。結果は一時フォルダに生成し、成功後に保存先へ確定する。途中の失敗・取消では既存の出力ファイルを置き換えない。出力ボタンの有効条件は音声解析完了と処理中でないことで、動画配置の有無には依存しない。

## 8. 実装順と受入検証

1. 技術検証: 1080pのH.264／HEVC、24／30／60fps、可変fps、縦動画、非ゼロ開始PTSでreaderの時刻対応と停止シークを確認する。3段同時再生と長GOPでCPU・メモリ・シーク待ちを測定する。
2. 共通モデルへの整理: VisualTrack、編集操作、保存version、履歴、クリップボード、管理画面を変更。画像だけの既存動作を維持する。
3. フレーム供給とMetal接続: reader管理、共通RenderSnapshot、キャッシュ、取消・世代検証、Transportを実装する。
4. UIと復旧: 動画読込・配置・トリム・素材開始、欠損復旧とMP4出力を接続する。
5. リファクタリング: 静止画と動画の重複した配置処理を統合し、デコーダーとUIを分離。画像専用名・不要な互換コード・リソース保持を見直す。
6. テストと実機検証後、./scripts/build-app.shで最終appを生成する。

受入テストにはタイムコードを焼き込んだ動画とクリック音の主音声を使う。素材音声には別の連続音を入れ、出力先に鳴らないことも確認する。

| 分類 | 確認内容 |
| --- | --- |
| モデル | 配置10秒／sourceIn3秒の対応、移動、両端トリム、素材境界、スナップ点なし、同段衝突、曲末、キーと演出位相 |
| 保存・編集 | JSON往復、Undo/Redo、コピー、複製、動画素材置換の一括検証、欠損復旧、旧形式の非上書き |
| デコード | PTSによるフレーム選択、VFR、Bフレーム、非ゼロ開始、最後のフレーム、失敗と正常EOFの区別 |
| 非同期 | 連続シーク、プロジェクト切替、削除、終了、古い完了通知、読込中の取消、メモリ解放 |

基準案は1080p/30fps素材・通常負荷で、安定再生時の偏差を概ね1出力フレーム（33ms）以内、10分再生で累積ドリフトなしとする。実音声の出力遅延を含め実測し、保証値とは区別する。シーク完了前は準備中として扱い、実測の中央値・95パーセンタイルと検証端末を記録する。reader方式で要件に届かなければ、AVPlayerItemVideoOutput方式または主音声を含む単一AVPlayer基盤への変更を比較し、採用方式を更新してから本実装を進める。

APIの採用はmacOS 14で利用可能なものに限定し、実装時にSDKのavailabilityを確認する。

## 10. 検証の範囲と残る制約

H.264の可変フレーム間隔・回転・順逆シーク、HEVC読込、3段1080pデコード、主音声による再生準備・再生・停止シーク、保存・履歴・コピー・動画入りMP4出力を自動テストする。3段1080pの処理時間はテストログへ出力する。10分の実音画偏差、非ゼロ開始PTSの実ファイル、長GOP・4Kの性能、実音声デバイスの遅延は未測定。33ms以内は目標値で、保証値ではない。

最終検証: 全60テスト成功。3段1080pデコードの中央値2.64ms、p95 6.94ms、後方シーク122ms（短い生成素材・当環境の参考値。描画・音声出力の実遅延を含まない）。build-app.shによる最新アプリ生成と署名検証に成功。

動画出力の追加検証: 音声付きH.264/VFR/回転素材と画像を3段に配置してMP4を生成し、全61フレームのPTS、選択時刻の合成ピクセル、音声長、主音声440Hzと素材音声1kHzの成分を確認する。HEVC素材の出力、既存ファイルの正常置換、出力途中の取消・素材尺不足・欠損時の既存ファイル保持も検証する。

## 動画の再生速度

動画選択時に「再生速度（倍）」を表示する。0.1〜16倍、初期1倍。DragValueFieldの直接入力・ドラッグ・中ボタン初期化を使い、ドラッグは終了時に1回確定しEscで取り消す。速度変更では配置開始と素材開始・終了を維持し、配置終了を開始＋元の配置長×旧速度/新速度へ変更する。隣接クリップや曲末を超える変更、1フレーム未満になる変更は拒否する。速度に伴う終了変更にはスナップを適用せず、素材区間を正確に保つ。主音声、手動キー、演出、項目別音楽同期の時間軸は曲時刻のまま維持する。速度はcontentへ保存し、Undo/Redo・コピー・複製に含める。速度未記録の動画は1倍とする。素材確認・置換・両端トリムも速度を考慮し、プレビューと出力は共通sourceTimeで素材時刻を評価する。

再生速度欄の右クリックではx0.25、x0.5、x1.0、x2.0、x4.0、x8.0、x16.0を選べる。現在の倍率へチェックを表示し、倍率の選択は数値入力と同じ長さ変更・配置検証を使う。

速度変更で後続クリップは移動しない。手動キーと演出の時刻は曲時間のまま保ち、クリップ外のキーも保持する。
