# 可変タイムラインレイヤーの設計

2026-11-19。ユーザー確定要件は「必要に応じてタイムラインのレイヤーを増やせる方式」。以下は実装した操作・初期値・制約。方式比較は [多数画像のレイヤー方式](VISUAL_LAYER_SCALING.md) を参照する。

## 1. 対象と基本原則

画像・動画・Spine・空クリップが混在する映像レイヤーを可変長にする。歌詞・スペクトラムの合成位置は現在の映像レイヤー群より前面のまま維持する。オートメーションレーンは映像レイヤーの下に展開する編集行であり、独立した合成レイヤーではない。

- 新規プロジェクトは3段、最背面の段を初期選択。最低1段を残す。
- 同じ段ではクリップの時間重なり禁止。別段では許可。
- 上の行ほど前面。追加・並べ替えでクリップの時刻・長さ・キー・演出・素材参照を変えない。
- 多数の空段を事前生成しない。段数上限は50段。負荷試験に基づく編集・保存の上限であり、全段30fpsの保証ではない。
- 初期範囲は平坦なレイヤー構造。複合クリップ・フォルダー・レイヤー共通演出・複数選択は別設計とする。

## 2. 画面と操作

タイムラインの左欄を共通のレイヤーヘッダーとして広げ、映像行にドラッグハンドル・名前・表示・ロック・メニューを置く。オートメーションの開閉は独立したボタンにする。表示する名称は「画像N」から「レイヤー名」へ統一する。

```text
[＋レイヤー]                         時間目盛り
≡ ● 🔓 前景                  [装飾────────]
  ▸ オートメーション
≡ ● 🔓 人物           [人物────────────────]
≡ ● 🔐 背景     [背景──────────────────────]
```

ヘッダー幅は共通定数で管理し、目盛り・全行・ゴースト・ヒットテスト・ドロップ・時間座標の原点を一致させる。名前は省略表示＋ツールチップ。狭いウィンドウでも時刻編集領域を確保し、詳細操作はメニューへ配置する。

| 操作 | 仕様 |
| --- | --- |
| ＋レイヤー | 選択段の直上に空段を追加して選択・表示領域へ移す。クリップ選択を解除、再生位置は維持 |
| ヘッダーメニュー | 上に追加／下に追加／前へ移動／後ろへ移動／名前変更／削除 |
| 並べ替え | ハンドルを上下ドラッグ。段と配下の編集行を一単位とし、元行を30%、掴んだ可視部分（ヘッダー・クリップ・展開レーン）を85%の追従表示とし、枠・影・最前面の挿入線を表示。mouseUpで確定、Esc・領域外ドロップで取消 |
| 名前変更 | メニューまたは名前のダブルクリック。Enter/正常なフォーカス離脱で確定、Escで取消。IME変換中に確定しない |
| クリップの段移動 | 本体を別段へドラッグ、またはインスペクターの移動先を選ぶ。別段移動は時刻を維持し、衝突時は全体を拒否 |
| 削除 | 空段は即時削除、クリップがある場合は件数を示して確認。元素材・登録素材は残す。最後の1段は削除不可 |

名前は前後空白除去後1〜80文字、改行不可。重複名は許可し、メニューでは前面からの表示順位を併記して区別する。新規名は既存名と重複しない最小の「レイヤー N」。名前は並べ替えで自動変更しない。順位は保存しない。

ヘッダーをクリックしてもシークしない。別段を選んだ場合はクリップ選択を解除。同じ段のヘッダー操作では既存クリップ選択を保持する。並べ替え・表示・ロックは選択と再生位置を維持する。削除後は直下の段、なければ直上を選択する。

並べ替え中は上下端付近で縦方向だけ自動スクロールする。横スクロール・ズーム・クリップ編集を併行しない。現在のクリップドラッグ・数値ドラッグと共通の操作状態で排他にする。

## 3. 表示とロック

表示スイッチは映像への参加を切り替える。非表示段もタイムラインに残し、クリップは薄く描く。プレビュー・出力の両方で非表示とし、選択・編集は可能。非表示を解除しても元のクリップ不透明度は保持する。

ロックの表示はロック中が🔐、解除中がグレースケールの🔓。ロックは編集防止。選択・内容確認・コピー・オートメーション開閉・行高変更・ロック解除は可能。クリップの追加・移動・トリム・削除・カット・複製・貼り付け・キー/演出編集、段の名前変更・削除・表示切替・段自身の並べ替えを禁止する。移動は元段と移動先の両方を確認する。ほかの段の並べ替えによる相対順序変更は許可するため、ロックは外観の固定を意味しない。

素材管理の全使用配置への置換・使用中素材削除がロック段へ影響する場合は処理を拒否し、対象段の解除を案内する。外部ファイル変更や再読込はロックでは防止しない。Undo/Redoは履歴全体の復元なので現在のロックを越えて適用する。

解析・読込・出力中、シート表示中は既存の編集制限に従う。確定前の入力は既存の終了処理へ渡し、不正な入力が終了できない場合は構造変更を保留する。

## 4. モデルと責務

```swift
struct VisualLayer: Codable, Equatable, Identifiable {
    var id: UUID
    var name: String
    var isVisible: Bool
    var isLocked: Bool
    var clips: [VisualClip]
}
// VisualTrack.layers: 背面 → 前面の順序
```

配列順を唯一の合成順とする。UIは逆順で表示する。slotは現行モデル/APIから削除し、旧形式の読込変換だけに閉じ込める。クリップの所属は包含するレイヤーで決め、clip側へlayerIDを重複保存しない。

VisualTrackに追加・削除・改名・移動・表示・ロックの値操作を集約する。並べ替えの移動先は配列添字を永続保持せず「このlayer IDの直前/直後」で指定する。同じ操作で同じ順序になる場合は変更なしとする。モデル検証でID一意性、最低1段、名前、段ごとの時刻順・重なり、既存素材/カーブの制約を確認する。

編集の可否はVisualEditor側の共通操作判定へ集約し、ボタン・キーボード・右クリック・ドロップが共有する。保存データの妥当性検証と、ユーザー操作のロック判定は分離する。

- 選択: selectedLayerID/selectedClipID。並べ替え後も同じIDを追う。
- 行高: visual/automation/Spineの段キーをlayer IDへ変更。演出は引き続きnode ID＋parameterで識別する。
- 開閉: layer ID基準。並べ替えやUndo/Redoで無関係の段を閉じない。削除段の開閉状態は同一プロジェクトの履歴復元に備えてセッション内に保持する。
- 行レイアウト: 共通の行記述配列を1回組み立て、描画・ヒットテスト・高さ・挿入線・縦スクロール範囲で共有する。画面外の行描画を省略する。

配置先のポップアップは各項目にlayer IDを持ち、名前と現在順位を表示する。ロック段は無効項目。非同期素材読込は開始時のlayer IDとプロジェクト世代を保持し、完了時に段の存在・ロック・区間を再検証する。配列位置が変わっても別段へ置かない。検証失敗は自動配置先変更をせず、操作を取り消して理由を表示する。

## 5. 直下段マスク

対象は所有段の配列上で直下にある1段。空段・非表示段・その時刻にクリップがない段を飛び越さない。最下段では対象なし。ロックはマスク適用に影響しない。非表示の所有段はマスクも無効。対象段が非表示なら描画しない。所有クリップの不透明度0で無作用となる現在の規則を保つ。

並べ替え・追加・削除で隣接関係が変わる場合、マスク詳細に「対象: 名前」を表示し、構造変更の仮表示でも対象名を更新する。対象なしは警告表示し、設定は保持する。毎回の確認ダイアログは設けない。マスクが設定された段をドラッグするときは挿入先と対象段を強調する。

例: 上から「マスク、人物、背景」で人物が対象。「マスク」と「人物」の間へ空段を追加すると対象は空段となり、人物には適用されない。

## 6. 描画・素材取得・性能

フレーム要求ごとに、全段のID/順序/隣接関係と、表示中の有効クリップから共通の描画計画を作る。VisualRenderLayerはlayer IDで識別し、合成順とマスク対象は計画から取得する。取得済みの有効フレームだけから隣接関係を推測しない。

非表示段のデコードと演出評価は省略する。出力前検証も描画参加する素材を対象とするが、プロジェクト全体の参照整合性は別途検証する。非表示段の欠損素材は保存参照を残し、再表示時に既存の欠損表示・出力停止へ戻す。可視段でその時刻に使われていないだけの素材を誤って除外しない。

並べ替え・表示切替はプレビュー世代を進め、古い非同期結果を適用しない。静止画の取得済み素材を使える場合は最新計画で即時再合成する。動画/Spineは必要な完成フレームがそろうまで直前の完成映像を保持する。名前・ロックだけの変更で素材デコードをやり直さない。

加工キャッシュはclip ID、素材キャッシュは素材の出自で管理し、段の並べ替えで無用に破棄しない。段削除・非表示化で不要になったキャッシュとデコードセッションは解放する。マスク中間面は同時使用期間を見て再利用し、GPU完了までフレームと作業面の参照を保つ。

10/20/50段の静止画、同数の静止画＋少数の重い演出、動画/Spine混在を分けて計測する。1080p/30fpsのGPU p95/最大、ピークメモリ、デコード数、シーク待ち、タイムライン操作時間、MP4の全フレーム一致を記録する。製品上限50段を追加・読込の両方へ共通適用する。プレビューが間に合わなくても出力はフレームを省略しない。多数素材のメモリ増加は今回の主要な実装リスク。

## 7. 保存・履歴・移行

レイヤーの名前/順序/表示/ロックはVisualTrackの値としてEditSnapshotに含め、自動保存とUndo/Redoへ接続する。段ドラッグは仮表示だけを更新し、mouseUpで1操作確定。Esc・同位置へのドロップは保存も履歴も作らない。名前変更は1入力セッション、各スイッチは1操作とする。行高は既存の表示設定の保存経路を維持し、編集履歴へ混在させない。

履歴復元後は存在する選択IDを保持する。削除されていれば隣接段または最背面へ補正する。選択の履歴自体は作らず、削除Undoでクリップを自動再選択することは保証しない。

保存形式はv19、読込範囲はv16〜19。v14→15→16→17の段階変換を読み込み境界で適用する。

旧slot昇順を背面→前面の配列へ変換し、既存UUIDは保持、空3段も残す。名前は旧slotから「レイヤー N」、表示true・ロックfalse。slot基準の行高を対応layer IDへ移す。未知slot、重複IDなど曖昧な入力は拒否し、自動修復しない。元Dataのバックアップ・曲長検証・atomic保存はProjectMigrator/ProjectStorageの共通経路を利用する。

## 8. 実装構成と整理

1. モデル/移行/行高: 安定ID、配列順、段操作、保存形式、固定fixtureを作る。
2. 編集: VisualEditor/PlacementEditor/TimelineView/SpineTimelineLaneと全ドロップ・コピー・キー操作をIDへ統一する。
3. 描画: ImageAssetStore/VideoFrameProvider/SpinePoseProvider/VisualFrameProvider/PreviewFrameReuse/MetalSceneRenderer、素材検証と出力を共通計画へそろえる。
4. UI: ヘッダー、メニュー、追加、名前、並べ替え、表示/ロック、マスク対象を接続する。
5. リファクタリング: 固定3段ループ・slot計算・重複した編集可否判定・段ごとの座標計算を除去。関連READMEと現行仕様書を更新する。
6. 回帰/負荷検証後に製品上限を確定し、最終コードで ./scripts/build-app.sh を実行する。

## 9. 受入条件

- 4段以上の重ね合わせと全段の前後順がプレビュー/MP4で一致する。
- 追加・削除・改名・並べ替え・表示・ロック・Undo/Redo・保存復元が一貫する。
- 段の並べ替えで選択・高さ・開閉・キー・演出が別段へ移らない。
- ロックはメニュー/直接入力/ハンドル/キー/貼付/素材管理を含め同じ規則で守られる。
- 空・非表示・最下段・隣接変更・連続マスクの対象が一致する。
- 読込中の段削除/並べ替え/ロック変更、古いプレビュー完了で誤配置や表示復活が起きない。
- 最小ウィンドウ・多数行・展開レーン・縦スクロール中のヒットテストとドラッグ取消を確認する。
- 対応3世代の固定fixtureから外観と行高を維持し、失敗したファイルを上書きしない。
- 負荷条件・上限の根拠を記録し、最新appのビルド成功を確認する。


## 10. 検証と性能の実測

全体241件（外部Spineサンプル1件スキップ・失敗0）、整理後の関連52件、最終の終了/Spine/レイヤー関連40件（外部サンプル1件スキップ）が成功。6段の順序/表示をMP4の全6フレーム・3画素位置で照合。画像・動画・Spineの6段混在、ヘッダー操作・改名・ロック・隣接マスク・保存/履歴・UUID行高・v11〜14読込を検証した。UI描画は `/tmp/my-movie-variable-layers.png` で確認。

参考計測（1080p、全画面単色を各段に持つ12フレーム、環境依存。最小対象Macの保証ではない）:

| 段数 | GPU p95 | 最大 | 試験プロセスの累積ピークRSS |
| --- | --- | --- | --- |
| 10 | 7.57ms | 34.70ms | 340.5MiB |
| 20 | 32.20ms | 62.18ms | 500.7MiB |
| 50 | 105.95ms | 158.89ms | 901.1MiB |

20段＋3段の放射ブラーは1フレーム41.48ms。初回加工・キャッシュ128MiB超過時は再加工が増える。全画面合成面が増えるので、50段で30fpsは保証しない。RSSは同一試験プロセスの累積最大値で、段数ごとの単独増分ではない。出力はGPU完了を待って全フレームを保存する。動画デコード128MiB、Spineキャッシュ256MiB/16素材、粒子画像128MiBの制限は独立して適用される。
