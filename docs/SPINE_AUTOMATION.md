# Spineアニメーションのオートメーション

更新: 2026-11-14。状態: 実装済み。クリップ共通時計の継続はユーザー確定仕様。既存のSpine初期機能は [SPINE_PHASE1.md](SPINE_PHASE1.md)。

## 1. 提示仕様の評価

提示されたUIを基本仕様として採用可能と判断する。

| ユーザーの案 | 設計上の扱い |
| --- | --- |
| 左欄にアニメーション名を上から列挙し、対応する水平線を表示 | 「アニメーション」レーンを追加し、左欄の各名前とグラフの線を同じYへ配置 |
| 基本的に水平線へスナップ | 選択モードでは必須スナップ。中間の名前・小数値を作らない |
| 曲線は常にホールド | 選択モードは固定ホールド。キー時刻で次の名前へ瞬時に切替 |
| 左側の右クリックで2アニメーションのブレンドを選択 | 左欄に「アニメーション切替」「2つのアニメーションでブレンド」を表示 |
| 最小値と最大値にアニメーションを指定 | 下端0%=A（最小側）、上端100%=B（最大側）をポップアップで指定 |
| ブレンド時はシングル曲線がデフォルト | 新規カーブ・新規キーの既定は既存のsingle。キー間中央○も共通操作 |

成立のために、時間、未キー項目、名前一覧の所属、モード変換を以下のように定義する。ユーザーが明示していない選択肢は提案として区別し、実装済みと扱わない。

## 2. レーンの所属と表示

保存と評価の単位はSpineクリップ。1クリップにつきアニメーション用レーンは1つとし、選択モードとブレンドモードを切り替える。画像/動画には表示しない。位置・回転・追加演出の数値レーンとは独立する。

現行TimelineViewの左欄はレイヤー内で共有されるため、レイヤー名そのものをアニメーション名で置き換えず、レイヤー配下の「アニメーション」レーン左欄に並べる。同じレイヤーに違うSpine素材がある場合も、選択クリップの名前・設定を表示する。アニメーションレーンには選択クリップのグラフだけを編集可能として描き、非選択クリップは本体から選び直す。異なる素材の同じYを同じアニメーションと誤認させない。

- 名前順は素材descriptorのanimations順。名前を保存するため、外部再出力で並びが変わっても選択内容は変えない。
- 名前一覧はクリップの有効な素材revisionに合わせる。再読込で名前が消えたら警告し、別名へ自動置換しない。
- 選択モードはN個を等間隔で上から配置する。N=1は中央の1本。上下の余白を確保し、最上段/最下段も掴める。
- 初期高さはmax(80pt, N×18pt+16pt)。選択モードは名前が潰れない同じ下限を使い、タイムライン全体の縦スクロールで全名へ到達できるようにする。長い名前は省略表示＋全文ツールチップ。
- ブレンドモードは上端B・下端Aだけを表示する。線間が連続した混合率であることを0〜100%の目盛りと「ブレンド」で示す。
- レーン開閉はレイヤー単位の既存状態を共有し、選択/Undoで勝手に閉じない。モードはクリップごと。キー/グラフへの選択や名前の右クリックでシークしない。

インスペクターの現在のアニメーション選択は、オートメーション有効時に「基準アニメーション」またはA/Bの設定へ表示を切り替え、評価結果を上書きする別の選択欄として残さない。レーン未作成では現行の単一再生を維持する。

## 3. 選択モード

キーはクリップ相対秒とanimationNameを持つ。名前を数値インデックスとして保存しない。

- キー作成・上下ドラッグは最寄りの名前線へ必ずスナップ。同距離は上側を選ぶ。モディファイアで解除しない。
- 左右は既存の時間スナップ設定に従う。名前への縦スナップと時間スナップは独立。
- 基準アニメーションはレーン作成前に選んでいた名前。最初のキーより前は基準を使い、その後は時刻r以下の最後のキーを使う。
- キーちょうどで新しい名前へ切り替わる。最終キー後はその名前を保持する。
- 同一時刻のキーは置換し、重複させない。直前と同じ名前のキーも編集の目印として許可するが、再生の再開始命令にはしない。
- 水平部分とキー時刻の垂直接続を描く。中央○は表示しない。キー右クリックは削除のみで、補間メニューは表示しない。

既存ImageKeyframeのvalueを丸めて名前に変換する方式は使わない。素材交換・名前順変更で別アニメーションに化けたり、数値補間から意図しない名前を通過したりしない専用の離散データにする。

## 4. ブレンドモード

下端Aと上端Bを、同じ素材に存在する異なる2つのアニメーションから選ぶ。名前のアルファベット順などで上下を決めない。素材に1つしかなければブレンド操作を無効にし理由を示す。

曲線値wは0〜1の混合率。表示は0〜100%。w=0はA単独、w=1はB単独、w=0.5は等量。両端にだけ吸着し、中間値は連続編集できる。音楽同期による混合率制御は今回の範囲に含めない。

- シングル曲線を既定とし、既存ImageCurveの時刻補間・中央○・描画サンプルを再利用する。中央○の変形がないsingleは直線。
- single/smooth/hold/pulse/waveの既存補間を選択可能とする。単一切替モードの「常にホールド」はブレンド側へ持ち込まない。
- キー値は0〜1を検証し、補間による範囲外も評価時にclampする。グラフもclamp後の値を描き、画面と出力を一致させる。
- 基準混合率の初期値は0%。キーより前は基準、キー以後はカーブを評価。最終キー後は最終値を保持する。
- 「A/Bを入れ替える」は名前の交換と、基準/全キーのw→1-w、中央オフセットの符号反転等を1操作で行い、同じ見た目を維持する。pulseの高低も反転して評価する。補間設定を保った正確な反転表現を実装できるまで、この補助操作は公開しない。

A/Bは数値の最小/最大欄ではなく名前選択欄とする。混合率を数値編集する場合のみDragValueFieldを使い、ダブルクリック入力・ドラッグ・中ボタン初期化・Esc取消を共通化する。A/Bの変更は区間長・キー時刻・混合率を維持し、結果の変更をすぐプレビューする。

## 5. 時間の規則

全アニメーションはクリップ共通時計で進む。切替時に再開始しない方式で実装するようユーザーから指定された。

曲時刻t、クリップ開始s、sourceIn=oに対してu=o+(t-s)。名前の切替でもuをリセットしない。A/Bも同じuを、それぞれの尺でループまたは終端保持して評価する。尺が異なる場合も秒を共有し、位相を0〜1へ正規化しない。現行のloop/sourceInはクリップ全体へ適用する。

例: sourceIn=0、クリップ2秒目でAからBへ切り替えると、Bの2秒地点を表示する。Bを0秒から始める仕様ではない。sourceIn=1ならBの3秒地点となる。この時計の継続はユーザー指定の仕様。

この方式は、名前キーの挿入・削除や混合率の0%通過で再生位相が飛ばず、後方シークでも同じ姿勢を再現できる。切替の都度先頭から始める「再開始」は、必要なら別設定として後段で設計する。ブレンドのA/B再生開始を混合率の0%／100%への到達で暗黙に決めない。

左トリムはsourceIn+=開始差、全キー時刻-=開始差として、切替位置とモーションを両方維持する。負時刻になったキーも保持し、区間開始時の状態や補間に使う。右トリムは終了だけ変更。本体移動はキー相対時刻/sourceInを維持する。

## 6. ポーズブレンド（追加提案）

Spine公式にはAnimationStateのクロスフェードとトラック重ね合わせがあるが、ユーザーが描く任意の混合率カーブを、そのまま経過時間依存のmixDurationへ置き換えない。

現行初期対応はボーンの移動・回転のみで物理OFF。これを維持し、A/Bの完全なローカルポーズを個別に評価してから混ぜる方式を採る。

1. 同じsetup poseからAを指定uで評価し、全ボーンのローカル移動・回転を取得する。未キー項目はsetup値になる。
2. 同様にBを独立に評価する。Aの評価結果をBの基準にしない。
3. ローカルXYは線形補間、回転は最短角度差で補間する。ちょうど180°は+180°側へ統一する。0%／100%は各単独評価の値を直接使用する。
4. setup由来のscale/shear等は維持し、混合済みボーンからworld transformを1回計算する。
5. その姿勢でweighted meshとclippingを計算し、既存描画packetへ渡す。切り抜き済み頂点や2枚の描画結果を補間しない。

Aが髪の回転、Bが瞬きだけをキーに持つ場合、A→Bで髪はsetupへ戻り、瞬きの動きが強くなる。両方を常に100%で同時適用する「重ね合わせ」とは異なる。最大値でA由来の動きが残る実装は、このモードの仕様としない。

現行のAnimation::applyをC境界内で再利用し、ローカル姿勢の読書きと混合だけ追加する。公式ポーズAPIとの具体的な接続は固定ランタイムで試験する。0/50/100%、±180°境界、未キー項目を持つfixtureで合格するまでブレンド完了としない。deform・slot/attachment切替・表示順・物理・制約のブレンドは今回の対象外で、既存の入力制限を維持する。

## 7. モード変更と削除

表示だけの変更ではなく評価データが変わるため、選択クリップへ1回のUndo/Redo操作として適用する。左欄の右クリックで対象クリップと現在モードを明示する。

- 切替→ブレンド: A/B選択画面を表示。初期Aは現在時刻の選択名、Bは別の先頭名。既存の基準/全キーがA/Bだけなら、A=0/B=1へ写し、既存区間はholdで動きを保つ。その後追加するキーはsingle。3つ以上の名前がある場合は変換を拒否し、「既存キーを削除してブレンドを作成」を明示的に選んだ場合だけ新しい基準0%のカーブへ置換する。0秒へ基準キーを追加して既存の負時刻キーを潰さない。
- ブレンド→切替: 中間混合は名前へ正確に変換できない。キー時刻/区間を保存した量子化で済ませず、既存カーブを削除して選択モードを作る確認を表示する。現在w<0.5はA、w≥0.5はBを基準候補とし、選択可能にする。
- 上記の新規作成は新モードの既定補間を使う。「singleが既定」と「変換時に既存holdを保持」を区別する。
- レーン削除: 選択モードは現在時刻の名前を固定再生のanimationNameへ戻す。ブレンドは現在wを固定混合として保持し、キーだけ削除する。勝手に近い片方へ丸めない。インスペクターには固定ブレンドのA/Bと混合率を表示し、再びレーン化できるようにする。

モード変更の取消は元データを維持する。ドラッグ中は仮評価のみ、mouseUpで1回確定、Escで取消。選択や右クリックは履歴に含めない。削除確認は情報を失うモード変更に限定する。

## 8. 保存モデルと統合

SpinePlaybackの再生指定を、single / selection / blendの型で表す。selectionは基準名＋専用名前キー、blendはA/B＋基準混合率＋混合率キーとautomatedを持つ。automated=falseではキーを持たず固定混合になる。sourceIn/loopは共通。選択キーには補間フィールドを持たせず、ホールドを型で保証する。

`SpineAnimationKey { id, time, animationName }` と `SpineAnimationSelection { baseAnimation, keys }` を新設する。blend曲線は数値補間の共通エンジンを使うが、ImageParameterへ架空の「アニメーション番号」を追加しない。ImageCurveに必須のparameter/range等は責務を整理し、時刻キー・補間計算を独立した数値カーブへ抽出して再利用する。既存変形/演出の評価結果を変えない回帰試験を必須とする。

TimelineViewのlane種別を数値レーン/Spine選択/Spineブレンドへ拡張し、ヒット判定・ドラッグ・削除・取消を共有、縦座標変換とメニューは種別で分ける。アニメーションレーンはImageParameter列挙に混ぜない。TimelineHeightsにも専用のレーン識別を追加する。

SpineAnimationEvaluatorが曲時刻から単一名またはA/B/wと共通uを返す。インスペクター、プレビュー、出力、キャッシュ判定は同じ要求値を使う。表示設定や最後に触ったキーから姿勢を決めない。非同期結果は既存世代照合で破棄する。

履歴/自動保存/コピー/複製/トリム/素材置換/出力前検証を同時に対応する。全名前（負時刻/区間外キーも含む）が素材に存在することを検証し、欠損時は参照と設定を保持して復旧を案内する。出力開始前に必要名を検証する。コピー後のclip/keyには新IDを発行する。

保存形式はProjectFile version 9。旧形式は既存のバックアップして新規作成する経路を使い、互換用の二重状態を残さない。

## 9. 実装順と受入条件

1. 選択専用モデル/評価器とホールドレーンを追加し、名前一覧・時間スナップ・負時刻キー・トリム・履歴/保存/コピーを検証。
2. ローカルポーズ2つのブレンドをC境界で試作。両端の単独一致と片方にしかキーのないボーン、回転角を検証。
3. A/B指定・混合率カーブ・固定混合・モード変更を接続。0/50/100%とsingle/smooth/hold/pulse/waveの描画値一致を検証。
4. 同レイヤーに別素材、1アニメーションだけの素材、多数/長い名前、外部再出力の並び変更/欠損を検証。
5. 同時刻の順再生・ランダムシーク・停止再開・MP4出力が一致することを確認。提供モデルで瞬きと髪の動きを切替/混合し、マスクも同じ姿勢に追従することを確認。
6. 数値カーブ抽出とlane責務を整理し、既存回帰検証・最小ウィンドウ配置・build-app.sh・署名確認を行う。

本書の範囲を実装済み。時計の継続・ポーズ混合・モード変換・固定ブレンドを共通の保存/履歴/出力へ接続した。物理ON、再開始モード、deform等の混合は含まない。

## 10. 根拠

- [公式Applying Animations](https://esotericsoftware.com/spine-applying-animations): AnimationStateの経過時間依存のmix、トラックによる重ね合わせ、Timeline APIの位置付け。
- [4.3 API reference](https://esotericsoftware.com/spine-api-reference): Animation.apply、setup pose、BonePose、world transform。
- 固定ソース: ThirdParty/spine-cpp/include/spine/Animation.h、BonePose.h、Skeleton.h、AnimationState.h。

ボーン姿勢を独立評価して混ぜる方式とUI規則はMV Studioの設計判断であり、公式のクロスフェードと完全に同じ挙動をうたうものではない。

## 11. 実装と検証

NumericCurveが変形カーブとSpine混合率の補間・描画サンプル・中央○を共有する。SpineAnimationAutomation.swiftが専用の名前キー/モード/評価・トリム・ID更新を持つ。SpineTimelineLaneが専用レーンの表示と操作状態を所有し、TimelineViewの行高さ・スクロール・既存確定経路へ接続する。SpineBridgeは同じuでA/Bを独立評価し、移動と最短角度でローカル姿勢を混合してから公式のworld transform/クリッピングを実行する。

SpineAutomationTestsで共通時計、0/50/100%の混合、未キー項目のsetupへの復帰、回転境界、ランダムシーク、変換のホールド保持、負時刻キー、保存・履歴・複製ID、名前スナップ/追加/取消/削除、中央○/補間メニュー/固定混合への復帰を確認する。SpineTestsのMP4試験は切替・ブレンドの両方を含む配置で全31PTS・プレビューとの画素比較を行う。専用レーンの描画PNGも目視確認する。

初期機能からの提供モデル試験も継続し、物理や特殊blendに対応したものと扱わない。今回のposeブレンドと、テクスチャのnormal/additive等のblend modeは別の機能。
