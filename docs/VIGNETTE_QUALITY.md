# Vignette品質改善

2026-11-18。減衰カーブと最終出力ディザを実装。丸み・中心XY・着色・明部保護・ACES・周辺ブラーは未実装の候補。

## 実装した仕様

VignetteRendererの専用CIColorKernelで、画面中央からのXY差を半幅/半高さで割った距離d、R=√2×範囲、W=max(R×ぼかし, 描画倍率/画面短辺)、inner=max(0,R−W)、t=max(0,d−inner)/W、透過率=1/(1+t²)²とする。強さをsとしてRGBへ(1−s)+s×透過率を乗算し、alphaは変更しない。中心の無影響領域と一次微分が連続し、基準半径で減衰を切らない。等減光線の縦横比はキャンバスと一致する。最小幅は短辺方向で1080p基準0.5px。操作は3数値を維持し、保存済み設定にも新しい描画を適用する。

最終outputColorに固定画素ハッシュのディザを実装。伝達関数変換後に、RGB共通の[-0.5,0.5)ノイズ×min(1/255,2×min(C,1−C))を加え8bit化する。黒/白は不変で、色付きのノイズや時間変化を加えない。出力全体で一度だけ処理し既定有効。

以下は実装に至った検討と今後の候補。

## 改善前の構成

MetalSceneRenderer.applyVignetteはCIRadialGradientとRGB乗算面をマスク合成する。画面中央基準、半対角長から範囲を計算し、強さ/範囲/ぼかしを保存・自動化する。ピクセル座標なので既に円形の距離評価であり、UVの縦横比補正を追加すると二重補正になる。

CIContextはlinear sRGB/RGBAh、中間Metal面はrgba16Float。アルファを維持してRGBを減光する。色調補正・色収差後、ブラーと高輝度抽出（ブルーム/グレア）前に適用する。最終outputColorは0〜1へ制限し、sRGBまたはRec.709伝達関数後に8bitへ書く。ACESトーンマッピングと明示的ディザはない。浮動小数点面があることとHDR素材/出力対応は別。

## 推奨する変更

### 1. 減衰カーブ

現行の放射マスクを専用カーネルへ置き換え、境界が目立ちにくい連続的な光学風カーブを使う。cosの入力は距離そのものではなく角度。理想的な投影でtheta=atan(r/f)とすれば、cos(theta)^4 = 1/(1+(r/f)^2)^2となり、三角関数やpi/2への強制クランプを避けられる。実レンズの遮蔽・瞳の形状まで再現するモデルではない。

既存の範囲/ぼかしを残す場合は、中央の無影響半径から遷移幅に距離を正規化し、その値を光学式へ渡す「光学風」の演出モデルとする。厳密な光学モデルと呼ばない。中心の係数1、強さ0で完全な無作用、減衰の単調性、範囲/ぼかし0の安定性を保証する。内外半径を超えた所で急に一定値へ切り替えず、一次微分の連続性も確認する。強さ100で全面黒に近づく設定を既定にせず、通常設定では暗部を残す。

追加操作はまず「丸み」のみを候補とする。画面比率の楕円〜円を連続的に調整し、既定値は比較画像で決める。中心XYは構図調整が必要になった段階で追加する。数値は共通DragValueField/キー/音楽同期/保存へ接続する。カーブの置換で保存済み設定の見た目が変わる点は明記する。

### 2. ディザ

ヴィネット面ではなく最終outputColorに追加する。伝達関数変換後・8bit量子化直前で、平均0、最大振幅を原則±0.5/255とする。リニア値に同じ1/255を加えると暗部で見えすぎる。アルファは変更せず、完全な黒/白の端では振幅を抑えて浮きやクリッピングによる偏りを避ける。

まずフレーム間で固定の画素座標ノイズを比較し、動画のちらつきと圧縮負荷を抑える。RGB共通のノイズで色ノイズを避ける。単純ハッシュとブルーノイズを比較し、目立つ模様が出る場合に後者を採用する。同じ出力サイズ/時刻で再現できることを保証する。H.264/AAC出力後にノイズが圧縮で失われる可能性があるため、非圧縮画像だけで判断しない。縞が完全に消える保証はしない。

ディザは全画面に作用する出力品質機能。ヴィネットの有効状態と結び付けず、UI追加や既定有効化は歌詞/スペクトラム/平坦色への影響を見て決定する。

### 3. 色と光

現行のリニアRGB乗算とアルファ維持を継続する。同一係数によるRGB乗算はRGB比を保つため、必ず彩度が落ちるという説明は採用しない。暗部の知覚的な見え方は別途比較する。彩度増加や青/暖色の着色は任意の演出とし、既定では中立色を維持する。

ブルーム前の適用は維持するが、減光により高輝度抽出のしきい値を下回る光は消え得る。「前ならハイライトが必ず保護される」とはしない。明部保護が必要なら独立した輝度依存の減光量を設計し、しきい値前後での不連続を検証する。

ACESはヴィネットの局所修正として導入しない。入力変換・作業色空間・出力変換を含む全体設計が必要で、既存の画像/動画/粒子の色と明るさが変わる。HDR/トーンマッピングを検討する別の作業とする。

### 4. レンズ演出

既存の色収差は一定方向のRGBずらし。レンズ風の放射状色収差とは別仕様なので、ヴィネットの減衰と暗黙に連動させない。周辺ブラーも独立した任意演出とし、コストと透明素材の縁のにじみを確認して追加する。初回の品質改善には含めない。

## 実装順と受入基準

1. 現行/光学風カーブを白・中間灰・暗灰・写真・イラストで比較し、式と既定値を確定。
2. 専用カーネルを導入。評価済みパラメーターをImageKeyへ含め、キャッシュ再利用とプレビュー/出力の共通処理を維持。
3. 最終ディザを独立実装しON/OFF画像と実MP4で比較。
4. 重複・責務を整理後、モデル/UI/保存/Undo/自動化/描画試験、全体テスト、build-app.shを実行。

描画試験は中心の輝度維持、単調減衰、同距離の対称性、丸み、解像度独立性、透明重ね合わせ、色比、強さ0/無効、極端値、ブラー余白の影響、キャッシュ更新を確認する。ディザは平均偏差と最大振幅・固定パターンの再現・黒浮きを計測する。1080pの暗いグラデーションと写真をMP4再読込し、縞・ちらつき・歌詞の輪郭・性能を比較する。
