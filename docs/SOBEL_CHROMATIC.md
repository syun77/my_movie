# Sobelフィルター＋色収差

2026-11-20実装。ユーザーが承認した設計に基づく現仕様。表記は一般的な「Sobel」を使用する。

## 参照作品と再現範囲

[Neon6 / Jzscwhat](https://www.shadertoy.com/view/Nl33D2)（2021-11-12、Neon5から派生）。ブラウザーでImageパスのコードを確認した。

- 輝度の8近傍からSobel勾配を取り、輪郭を強調する。ただし近傍は対称な固定3×3ではなく、時刻で動く非対称配置。
- 色収差は画面中心からの距離の3乗で強まり、時間で脈動する。RGBはそれぞれ異なる斜め方向へずれる。一般的な中心から放射状の色収差とは異なる。
- `sin(2t)`が0.4〜0.8の間は輪郭、それ以外は色収差へ切り替わる。両者の常時加算ではない。
- 輪郭側には負の底を持つ非整数乗があり、色収差側も赤成分をalphaへ流用している。これらをそのまま移植するとNaNや意図しない透過が生じる。

移植の目的は「時間で切り替わるネオン輪郭と揺れる色ずれ」の再現。負数powと素材依存alphaは採用せず、輪郭色と独立したcoverageへ置き換える。ピクセル完全一致は保証しない。参照作品のソース・入力映像は同梱しない。参照原文のライセンスは未確認のため転用せず、以下の仕様に基づく専用Metal処理を独自実装する。

## 追加操作と適用範囲

「色・質感」へ「Sobel＋色収差」を追加し、既存の「色収差」の次に置く。EffectKindは専用のsobelChromatic、payloadはImageEffects.SobelChromaticとする。既存色収差の設定・描画は独立して維持する。

チェーンの任意位置に置く加工ノード。同種1つまでという既存制約を共有する。その位置までに蓄積した素材・図形・粒子・発光を読み、後段へ渡す。画像・動画・Spineを共通に扱い、他レイヤーや歌詞・スペクトラムは読まない。空入力は透明のまま。後段ブルームで輪郭を発光させる構成も可能。

## 設定パネル

| 項目 | 範囲 | 初期値 | 意味 |
| --- | --- | --- | --- |
| 表示モード | 自動切替／輪郭／色収差／合成 | 自動切替 | 自動は元作品の切替条件、合成は輪郭を色収差へ加える |
| 適用率 | 0〜100% | 100% | 入力と加工結果の混合率 |
| 輪郭の強さ | 0〜400% | 100% | Sobel勾配のゲイン |
| 輪郭の幅 | 0.25〜8px | 1px | 1080p基準の近傍倍率 |
| 輪郭色 | RGB | 水色（0.20, 0.85, 1.00） | 元コードの不定な色計算の代わりに使用 |
| 色ずれ量 | 0〜100px | 32px | 1080p画面の角での最大チャンネル変位 |
| 動きの速さ | 0〜400% | 100% | 元作品の時刻に対する倍率 |

全数値をDragValueField、手動キー、項目別音楽同期へ接続する。初期状態ではキー・音楽同期なし。数値の直接入力・方向固定ドラッグ・Shift微調整・中クリック初期化・Esc取消を共有する。モードと色は離散設定で、初期版では自動化しない。モードを変えても非表示側の数値・キーは保持し、未使用項目を無効表示する。

適用率0またはノードOFFは入力をそのまま渡す。輪郭モードの強さ0は黒い輪郭面となり、原画復帰ではない。原画との重ね合わせは「合成」または適用率で調整する。

## 時間評価

`localTime = 曲時刻 − clip.start`。`t = (localTime + phaseOffset) × speed / 100`とし、共通のクリップ相対時計を使う。負の時刻も同じ式で評価し、フレーム番号、再生履歴、乱数、壁時計には依存しない。

自動切替は `0.4 < sin(2t) < 0.8` のとき輪郭、それ以外は色収差。境界のクロスフェードは初期版では行わない。速度0はt=0で静止する（自動切替では色収差側、時間変位0）。停止状態で輪郭を見たい場合は輪郭モードを選ぶ。

左トリム時はphaseOffsetへ開始位置の差を加え、同じ曲時刻の見た目を保つ。通常の移動・複製・並べ替え・OFF/ONは位相をリセットしない。速度のキー/同期は既存演出と同じ時刻への乗算で、積分しないため、急変時の位相ジャンプは許容する。評価済み時刻と全設定をキャッシュキーに含める。

## 描画アルゴリズム

SobelChromaticRendererと専用Metal computeを追加し、既存process内でcurrent→nextのping-pongを使う。入力は既存の線形RGB中間面、画面外は透明。座標・上下方向はCore Imageと同じ契約に統一する。

### 輪郭

参照の近傍配置を保ち、1080p基準で `i=1.8 cos(6t)`、`j=3.2 sin(6t)` とする。幅をwとするとX/Yそれぞれの候補は `(-i×w, 0, j×w)`。中心以外の8点へ元作品と同じSobel係数を適用する。GPU参照距離には描画倍率を掛け、余白を足した座標で読む。線形補間を用いる（参照作品のnearestとは細部が異なる）。ハードウェア線形補間の有限精度により、CPUの倍精度参照との差を輪郭最大0.03・色収差最大0.004（線形RGB）まで許容する。

各サンプルの色基準係数は既存チェーンの `k=max(alpha, min(1,max(R,G,B)))`。k=0は黒、それ以外はRGB/kを非負のsRGBへ変換し、係数(0.3,0.59,0.11)で明るさを求めてkを掛ける。これによりalpha0の加算光と半透明の強度を残す。HDRは検出の入力で0〜1へ制限し、元画像のHDR RGBは別に保持する。

`edge = min(4, length(gradient)² × strength/100)` と定義する。輪郭色をsRGBから線形へ変換し、RGB=色×edge、alpha=近傍8点と中央のalphaの最大値、とする。輪郭モードの平坦な不透明領域は黒、完全透明領域は透明。入力にalpha0の加算光だけがあればalpha0の輪郭光を生成する。alphaをRGBへ流用しない。

### 色収差

余白を除いた映像枠から左下原点UVを求める。`r=clamp(length(uv−0.5)/sqrt(0.5),0,1)`、`a=r³×abs(sin(2t))×色ずれ量`。

参照の方向を正規化した `dR=(-1,-1)/sqrt(2)`、`dG=(-1,3)/sqrt(10)`、`dB=(1.8 cos(6t),0)/sqrt(10)` とし、各チャンネルをuvではなく画面pxへ換算した `位置+a×d` から読む。Bは元作品同様に方向と距離が時間変化する。指定量は最大変位の上限であり、全チャンネルが常に同距離にはならない。距離は画面基準で等方的とし、元作品のUV依存の縦横伸縮は引き継がない。

RGBは各サンプルのpremultiplied成分を組み合わせ、alphaは3点の最大値とする。alpha0 RGBの光も捨てない。入力RGBをSDRへクランプせず、既存色収差の減光gainは適用しない。

### 合成・適用率

合成モードは色収差RGB＋輪郭RGB、alphaは両者の最大値。輪郭による光量増加は許容し、最終出力変換まで保持する。最終的に入力と結果のRGBAを適用率で線形混合し、クリップ共通不透明度はチェーン完成後に一度だけ適用する。

参照近傍の最大距離は軸ごと3.2×幅、色収差は最大100px。supportはモードに応じて最大サンプル距離＋補間1pxを計上する。両処理は同じ入力を独立して読むため、このノード内では半径を足さず最大値を使う。前後の別ノードとの余白は既存チェーンと同様に累積する。距離rは余白領域で1に制限し、確保幅を超える変位を防ぐ。中間面の余白は偶数pxに切り上げ、余白変更でも図形の微分アンチエイリアスの2×2画素配置を保持する。

## モデル・保存・接続箇所

ノードにisEnabled、mode、amount、edgeStrength、edgeWidth、edgeColor、chromaticAmount、speed、phaseOffsetを保存する。数値のfinite/範囲、色、モードを検証する。曲線・同期・表示範囲はEffectNodeが所有し、新しいImageParameterをノードIDと組にして参照する。EffectKindの既存整数値は動かさず末尾へ追加する。

保存はProjectFile v17、読込はv17〜20。v14→15は既存ノードを保持し、新演出を追加しない。v14以前へのSobel payload混入は拒否する。対応窓から外れたv11→12変換器は保持しない。ProjectMigratorの未知項目検出・バックアップとatomic保存を共有する。

主な実装箇所:

- ImageEffects / EffectChain / ImageAnimation / EffectAutomation: 型、既定値、検証、自動化参照、削除、コピー、トリム時計。
- EffectCategory / ImageEffectsEditor: 追加メニュー、設定パネル、共通の確定/取消通知。
- SobelChromaticRenderer / Shaders/Scene.metal / MetalSceneRenderer: 時刻評価、GPU処理、support、キャッシュ。
- ProjectFile / ProjectMigrator / 保存fixture、関連仕様とテスト。

追加・削除・モード/色変更・数値ドラッグは既存経路でUndo1回・保存1回。仮変更はプレビューだけに使う。レイヤー固定数への依存や専用の映像取得処理は追加しない。

## 実装・検証の手順

1. モデル・時刻評価・保存移行・数値定義を追加。CPU参照計算で各モードと切替境界を確定する。
2. GPU加工を接続し、黒白/色境界/透明PNG/alpha0発光でCPU参照と比較する。
3. UI・キー・同期・履歴・コピー・トリムを接続する。
4. 責務・重複・命名・support計算を整理し、関連回帰、MP4、性能を確認する。最終コードでbuild-app.shを実行する。

受入条件:

- 平坦色、縦横と斜めの境界で勾配の方向・幅・強さが参照計算に一致し、NaN/Infが出ない。
- 自動切替のしきい値直前/同値/直後、色収差の中心/辺/角、速度0と最大値を検証する。
- 適用率0/OFF/バイパスは入力一致。半透明と加算光に黒縁や不意の消失がなく、画面外へRGBを繰り返さない。
- ブルーム/粒子/マスクとの逆順で意図した差が出て、余白変更で中心や色ずれ量が動かない。
- 画像・動画・Spine、空クリップ、上下方向、50%プレビューと1080p出力を比較する。
- シーク順に依存せず同時刻が一致。左トリム、コピーの新ID、キー/同期、Undo/Redo、保存復元、移行で設定と参照を保持する。
- プレビューとMP4の同時刻を比較する。映像圧縮差は許容し、切替フレームは一致させる。
- 1080pの1段/3段および現行可変レイヤーの実用構成でGPU時間・ピークメモリを計測する。全画面CPU読戻し、ノード数比例の中間面常駐を追加しない。リアルタイム性能は計測前に保証しない。
