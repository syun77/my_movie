# プロジェクト形式の世代管理と移行

## 対応範囲

保存は現行v19、読み込みはv16〜19（現行＋直前3世代）。整数の `version` はアプリのリリース番号から独立した保存スキーマの番号とする。逆変換は行わない。v15以前、未来の番号、番号欠落・不正値、破損JSONは元ファイルを保持して拒否する。

保存構造、必須項目、単位、列挙値、保存値の意味を変更するときは番号を増やす。追加項目も新スキーマとして番号を増やす。UI調整や保存契約が変わらない最適化では増やさない。各版のキー、型、単位、欠落時の意味を固定し、世代別fixtureを維持する。

## 実装と段階変換

`ProjectMigrator` がヘッダーを先に読み、範囲判定後にJSONを1世代ずつ変換する。現行ProjectFileへdecodeした後、設定、トラック、IDを検証する。旧キーの解釈を編集・描画モデルへ持ち込まない。

- v16→17: グラデーション背景のpayloadと7数値を許可する。既存ノードを保持し、新背景を自動追加しない。v16以前へのgradientBackgroundと新パラメーター混入（行高さ設定を含む）は拒否する。

- v17→18: クリップと演出ノードのcurvesをParameterAutomation（キー方式）へ変換する。キーIDと値を保ち、表示上下限をautomationRangesへ移す。旧形式にautomationsが混入した場合、重複範囲や不正な旧カーブは拒否する。LFOを自動追加しない。

- v18→19: 渦巻き粒子のpayloadと数値項目・粒子画像の4数値を許可する。既存ノードを保持し、新演出は自動追加しない。v18以前への新payload・パラメーター混入は拒否する。v15→16変換器は対応範囲外のため保持しない。

旧形式で省略可能だった既定値（歌詞書式、スペクトラムなど）は読み込み境界で固定値を補う。現行のUI初期値が変わっても過去ファイルの解釈を変えない。Codableが無視する未知の項目は、decode後の再encodeと構造を照合してデータを黙って捨てない。不正な列挙値や必須項目欠落は項目パスを含めて通知する。

`ProjectStorage.readForOpening` はProjectFile、変換元番号、元Data、元URL、適用した段階の報告を返す。`read` は検証済みProjectFileだけが必要な呼び出し用で、ファイルを変更しない。設定を変換する必要のない隣接世代も、その世代で許可されたpayloadを検証してから番号を進める。

### 対応境界

v15以前は対応範囲外。v16〜18の未知の演出・項目は初期値へ置き換えず拒否する。対応窓の外の変換器は保持しない。

## 読み込み・バックアップ・自動保存

1. 元データを読み、メモリ内で変換・検証する。この段階では元ファイルに書き込まない。
2. 音声解析とプレイヤー準備、歌詞/素材配置の曲長検証を行う。
3. 旧形式の場合は、編集状態を切り替える前に `commitMigration` を呼ぶ。
4. NSFileCoordinatorで書き込みを調整し、元ファイルが読み込み時のDataと一致することを確認する。
5. 同一フォルダに元Dataをそのまま新規バックアップする。例: `song.wav.mvproject.v10.<UUID>.backup`。既存バックアップは上書きしない。
6. 元Dataとの一致を再確認し、現行形式をatomic保存する。成功後に最後のプロジェクトURLを記録する。
7. 画面と履歴を現行モデルへ切り替え、通常の自動保存を開始する。移行直後の重複保存は行わない。

移行成功はステータスに変換元/先番号とバックアップ名を表示し、ツールチップに変換段階とバックアップのフルパスを表示する。移行自体をUndoへ登録しない。

バックアップ作成、現行保存、音声解析、曲長検証に失敗した場合は元ファイルと直前の編集モデルを保持し、エラーを表示する。保存失敗後も作成済みのバックアップは残す。読み込み後の外部変更は検出時に上書きを停止して再読込を案内する。ファイル調整に参加しない外部プロセスによる最終確認後の書換まで排他的に防ぐものではない。

起動復元と音声選択は同じopenProject経路を使う。素材欠損の参照保持と復旧、出力前の使用素材検証は既存の方針を使う。形式読込エラー時の「バックアップして新規作成」は内容を引き継ぐ移行とは別の明示操作であり、キャンセルすればファイルを保持する。

## 検証と保守

`Tests/MVStudioTests/Fixtures/Projects` にv16〜19の受入用固定JSONと、対応範囲外となったv8〜15の固定JSONを保持する。fixtureは各世代の型定義と照合した合成データであり、ユーザーの実プロジェクトそのものではない。

ProjectMigrationTestsは以下を確認する。

- 全4形式の受入、旧3形式の段階変換、現行保存後の再読込。
- 歌詞連結、素材参照、Spine再生、動画時刻、キーと補間評価、演出、音楽同期、行高の保持。
- 範囲外番号、欠落番号、JSON破損、不明項目/列挙値、重複ID、不正区間、新payloadの旧形式への混入の拒否。
- 元Dataと一致するバックアップ、再読込時の移行不要、外部更新検出、バックアップ/保存失敗時の元ファイル保持。
- 起動復元/明示読込で、移行保存時点では以前の編集状態を保持していること、バックアップ後に1回だけ書くこと、曲末超過やバックアップ失敗で画面・参照URLを切り替えないこと。

ファイル調整とAppKitを含む試験はmacOSサービスへアクセスできる環境で実行する。版更新時はcurrentVersion、対応する変換段階、fixtureと境界試験、文書を一緒に更新する。対応窓の外に出た変換器は、残る経路に必要なものを除き削除する。
