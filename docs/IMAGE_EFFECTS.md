# 画像クリップの追加演出

画像クリップごとにガウスブラー、ブルーム、光の粒子、舞い上がる火の粉、雪、光の粒子2を設定する。既存の位置・拡大縮小・回転・拍／トランジェント連動と組み合わせられる。初期値と上限は下表のとおり。数値欄は整数で調整する。

## 編集画面

「画像・演出」タブでタイムライン上の画像クリップを選び、インスペクターの折りたたみ式「追加演出」を開く。「＋ 演出を追加」から種類を選ぶと初期値で有効になり、その設定を表示する。追加済みの演出を種類のメニューで選び、有効チェック、削除、パラメーター編集を操作する。無効化すると設定を保持したまま描画を止める。1クリップにつき各種類1つで、追加済みの種類はメニューで選択不可にする。フィルターと粒子の合成順は固定し、一覧にもその順序で表示する。

| 演出 | 設定項目（初期値、範囲） | 見え方 |
| --- | --- | --- |
| ガウスブラー | 半径 8 px（0〜64 px） | 選択した画像をぼかす。0で元の画像を使う。 |
| ブルーム | 輝度しきい値 65%（0〜100%）、半径 24 px（1〜96 px）、強さ 60%（0〜200%） | しきい値より明るい部分から光が広がる。強さ0で光を描かない。 |
| 光の粒子 | 発生源 1（最大4）、発生源ごとの個数 90（1〜200）、基準直径 8 px（2〜32 px）、基準速度 60 px/秒（0〜300 px/秒）、曲線の強さ 100%（0〜200%）、基準色は青紫、不透明度 65%（0〜100%） | 発光点が曲線を描き、後を追う星形の粒が色を変えながら消える。基準速度0では位置を固定し、明滅と色の変化は続ける。 |
| 舞い上がる火の粉 | 個数 90（1〜200）、大きさ 20 px（4〜80 px）、上昇速度 160 px/秒（20〜420 px/秒）、横風 24 px/秒（−240〜240 px/秒）、揺れの速さ 40%（0〜200%）、明るさ 85%（0〜100%） | 大小の火の粉が画面下から揺れながら上昇し、赤みを帯びて消える。横風の正値は右、負値は左。 |
| 雪 | 個数 200（1〜200）、大きさ 22 px（2〜64 px）、落下速度 220 px/秒（20〜700 px/秒）、横風 20%（−100〜100%）、不透明度 55%（0〜100%） | 大小の白い粒が横に揺れながら画面全体を落下する。横風の正値は右、負値は左。0%でも緩やかな横揺れが残る。 |
| 光の粒子2 | 発生数 150（1〜200）、彩度 100%（0〜100%）、速度 100%（0〜200%）、不透明度 100%（0〜100%） | 丸い光が、粒ごとに軌道の大きさと角度を変えながら動く。速度0%で静止する。 |

「光の粒子」の発生源欄で番号を選び、＋／−で追加・削除する。X・Yは映像の左上を原点とする1080p基準の軌道中心。Xは0〜1920、Yは0〜1080。初期位置はX960・Y508。発生源の位相は個別に保存し、個数、色、速度などは全発生源で共有する。発生源の記録がないプロジェクトでは初期位置に1つ置く。

火の粉は橙色の光と明るい芯を持ち、画像の上へ加算合成する。下部の発生位置、寿命、見かけの奥行きは粒ごとに変わり、消えた粒は別の位置で発生する。光の粒子と併用すると火の粉を後から描く。広い風の流れと細かな揺れを2層の補間ノイズで作る。「揺れの速さ」はノイズをたどる速度を変え、0%では揺れを止める。未設定時は40%。上昇・横風・明滅は独立して評価する。橙色の細長い芯とにじみの向きや幅を粒ごとに変える。参考は添付のJan Mróz（jaszunio15）のシェーダー。 [Shadertoy](https://www.shadertoy.com/view/wl2Gzc)、[CC BY 3.0](https://creativecommons.org/licenses/by/3.0/)

雪は画面全体に分布し、大きな粒ほど速く落ちる。画面外まで落下した粒は上端の外から再び降る。粒の中心から外縁にかけて不透明度を滑らかに下げ、画像へ重ねる。火の粉と併用すると雪を後から描く。

光の粒子2は粒ごとに異なる周期で正弦・余弦の軌道をたどり、画面中央を基準に軌道が拡縮・回転する。粒の直径は1080p基準で40〜76 px。丸い光を雪の後で線形sRGBの画像に加算する。彩度100%は粒ごとの固定RGB色、0%は同じ輝度の無彩色。発生数は同時に動く粒の数で、増減しても共通する粒の軌道と色は保つ。光は粒の外縁までに透明になり、粒が届かない画素は元の映像のまま表示される。不透明度で加算する光の強さを調整する。発生数と彩度が未保存の場合は150と100%を使う。

pxは1920×1080の映像を基準とし、素材の元解像度やウィンドウの大きさから独立させる。各数値欄は `DragValueField` を使い、ダブルクリックで直接入力、中ボタンで初期値へ戻す。左右ドラッグ中は仮プレビュー、mouseUpで1回のUndo／自動保存、Escで取消。追加・削除・有効切替・色変更の確定も各1操作とする。編集中の再生位置は維持し、再生ヘッドが対象区間外なら「クリップ区間外」と表示する。

初期版ではクリップ区間全体に一定の設定値を適用する。粒子の動きは時刻から自動生成する。演出のキーフレーム、音声連動、プリセット、演出専用トラックは後続候補とする。

## 合成順と演出の作用範囲

背景 → 画像1 → 画像2 → 画像3 → スペクトラム → 歌詞の順に描く。各画像レイヤー内では次の順序を使う。

1. 既存の手動変形と自動拡大を評価し、画像をキャンバス座標の透明な描画面へ配置する。
2. その画像にだけブラーを適用する。透明画素の色がにじまないよう、プリマルチプライドRGBAをフィルターに渡す。処理範囲はフィルターの裾まで確保し、映像の外側で最終的に切る。画像端は透明側へ自然にぼける。
3. ブラー後の画像からブルームを生成する。線形RGBの輝度にしきい値を適用し、しきい値から白までの範囲を0〜1へ正規化し、入力アルファを掛けたマスクで発光色を重み付けしてぼかす。しきい値100%は発光なし。ぼかした発光RGBに強さを掛けて入力RGBへ加算し、入力アルファと強さを掛けた発光マスク（上限1）の和集合を出力アルファとする。フィルターの作業用テクスチャには浮動小数点を使い、SDR範囲への制限は最終出力で行う。
4. 演出済みの画像を下のレイヤーへsource-overで合成し、その上に粒子を描く。粒子は画面座標で描き、対象クリップの画像枠の外にも広がる。後から描く上段の画像で隠れ、ブラーやブルームの入力にもならない。スペクトラムと歌詞は全画像・全粒子より前に描く。

画像と演出の有効期間は `start <= t < end`。クリップの素材が欠損している間は画像と演出をまとめてプレビューから省略し、既存の欠損警告と書き出し前検査を使う。

## 保存と粒子の時刻

- `ImageClip.effects` に型付きの `ImageEffects` を持たせる。`blur`、`bloom`、`particles`、`embers`、`snow`、`orbs` はそれぞれ任意の値型で、設定値と `isEnabled` を持つ。未追加はnil。画像素材を共有しても、演出はクリップごとに独立する。素材差し替えや段移動では演出を保持する。
- 保存はProjectFile version 5を使う。version 4の構造はそのまま読んで `effects` の欠落を空として扱い、通常の保存時にversion 5を出力する。演出を含むファイルを古いアプリで開いた際に無視して上書きすることを防ぐ。未知の版や不正データは読込エラーにして、元ファイルを保持する。
- 編集確定と読込で型、有限性、範囲、RGB値を検証する。光の粒子、火の粉、雪には固定幅の乱数シードと位相オフセット秒を保存する。光の粒子2の配色は粒番号で決まり、位相オフセット秒はクリップごとに保存する。Undo／Redoは既存の `ImageTrack` スナップショットに含め、`ImageEditor` のプレビューと確定の通知を再利用する。
- 光の粒子は明るい発光点を複数周期の曲線に沿って動かす。粒は発光点が少し前に通った位置に集まり、個体ごとに異なる寿命で散って消える。「基準速度」で動きの時間を調整する。「曲線の強さ」0%では水平な直線上を加減速し、値を上げると軌道の振れ幅が広がる。未設定時は100%。基準色を起点に約20秒で色相が一周し、発光点と粒に色相差を付ける。星形の光と動き・色の参考はEmmanuel Keller（Tambako）の作例。 [Magic particles](https://www.shadertoy.com/view/ld3GWS)
- 火の粉は同じクリップ相対時刻から発生回数と寿命内の時刻を求める。粒子の位置、明るさ、発生位置の変化は固定シードから再現する。
- 左トリムは `phaseOffset` にクリップ開始の差分を足し、残った区間の見え方を保つ。右トリムはオフセットを維持する。クリップ全体を移動すると演出の位相もクリップと一緒に移動する。左トリムの計算はタイムライン操作と開始時刻欄で共有する。

## レンダリング方式

`PreviewView` と `VideoExporter` は `MetalSceneRenderer` を共有する。画像の変形、ブルームの明部抽出、最終合成はMetalを使う。素材の色変換とガウスフィルターはMetalバックエンドのCore Imageで処理する。

| 方式 | この機能での評価 |
| --- | --- |
| Core Graphics中心＋Core Imageフィルター | 既存コードへの変更が少ない。フィルター結果を各画像・各フレームでCGImage化して戻す場合、GPUとCPUの同期や転送が再生時の負荷になる。 |
| Metal合成＋Core Image（採用） | 画像フィルターの中間結果をGPU上で使い、Metalで画像・粒子・前景を合成できる。ガウスぼかしはCore Imageを利用し、粒子描画と最終合成にMetalのパイプラインを持つ。 |
| 全工程を独自Metalシェーダーで実装 | ブラーの精度やパスを細かく制御できる。フィルターの自作と色・アルファの検証範囲が広い。計測で特定の処理がボトルネックと判明した段階で個別に検討する。 |

- **共通入力と合成**。編集画面と書き出しで同じフレーム評価を呼び、時刻、変形、演出値、レイヤー順を共有する。作業座標は1920×1080。Core Imageで色変換した素材テクスチャを有効な素材ごとに保持する。Metalで固定サイズの描画面に変形を適用し、Core Imageのフィルターへ渡す。粒子はインスタンス描画する。GPU処理は同じデバイス・コマンドバッファに順序どおり記録する。色は入力プロファイルを尊重して線形sRGBで処理し、アルファと座標系は入力境界で統一する。 [AppleのCore Image／Metal連携](https://developer.apple.com/documentation/coreimage/cicontext/render%28_%3Ato%3Acommandbuffer%3Abounds%3Acolorspace%3A%29)
- **既存の前景描画**。歌詞とスペクトラムはCore Text／Core Graphicsの描画を透過テクスチャへ出し、Metalで前景に合成する。歌詞は表示内容・書式・解像度が同じ間は再利用し、スペクトラムは必要な枠だけ更新する。画像は既存のImageIO経路でデコードする。GPU側の画像キャッシュはデコード結果の同一性を照合し、差し替えや再読込で更新された画像を再処理する。CPU描画をアップロードするテクスチャにはGPUごとの既定のストレージモードを使う。 [Appleのストレージモード設定](https://developer.apple.com/documentation/metal/setting-resource-storage-modes)
- **プレビュー**。内部で960×540に描画し、`MTKView` が完成テクスチャを16:9で表示する。効果のサイズは1080p基準で評価して縮尺を適用し、粒子の位置と時刻は書き出しと共通。時刻は音声再生位置を使い、停止中はシークや編集などの変更時に描画する。表示が遅れた場合は最新のプレビュー要求を優先する。素材の読込要求は世代で識別し、シークなどで対象が変わった場合は古い読込結果を適用しない。 [AppleのMTKView](https://developer.apple.com/documentation/metalkit/mtkview)
- **書き出し**。プールから取得したMetal互換のBGRA `CVPixelBuffer` を `CVMetalTextureCache` でテクスチャにし、GPU完了後に既存のAVAssetWriter経路へフレーム順に渡す。フレーム時刻は `index / 30`。曲末がフレーム境界の途中にある場合は、最後の映像フレームを次の境界まで保持する。キューを制限し、ライターが詰まったら待機する。GPU処理中のテクスチャやライターが保持するバッファを再使用しない。PCMにデコードした音声と映像を同じAVAssetWriterへ送り、H.264／AACのMP4を生成する。音声はモノラルまたはステレオで保存する。プレビューはsRGB、MP4はRec.709 SDRとして出力変換と色タグを揃える。 [AppleのCVMetalTextureCache](https://developer.apple.com/documentation/corevideo/cvmetaltexturecache-q3j)、[AVFoundationの色設定](https://developer.apple.com/documentation/avfoundation/setting-color-properties-for-a-specific-resolution)
- **負荷と失敗時の扱い**。無効な演出のパスは省略し、処理済み画像と中間テクスチャを再利用する。処理済み画像のキャッシュキーに素材世代・変形・フィルター設定・解像度を含め、キャッシュには容量上限を設ける。GPU処理中のフレームはプレビューと書き出しそれぞれ1枚まで。処理済みの画像テクスチャのキャッシュは各レンダラー128 MiBを上限とする。中間テクスチャは再利用し、Core Imageの内部キャッシュを120フレームごとに解放する。GPUを初期化できない場合や書き出し中の描画失敗は明示し、演出を省いた動画を成功扱いにしない。対象MacでのGPU／エンコーダ動作は実機検証で確定する。

## 実装順と受け入れ条件

1. **技術検証**。透明PNGと3段の画像を使い、同じ共通フレームを `MTKView` とAVAssetWriterへ出す。現行描画と比較して画像の位置・回転・アルファ・歌詞・スペクトラム・音画同期を確認し、圧縮前の画素を同じ色空間に変換してプレビューと出力を比較する。最小対象MacはmacOS 14対応機から選定する。MetalシェーダーのソースはSwiftPMのリソースとして `scripts/build-app.sh` でアプリへ同梱し、実行時にMetalライブラリへコンパイルする。
2. **ブラーとブルーム**。保存・Undo／Redo・数値編集から書き出しまでつなぐ。半径0／強さ0／無効化、透明PNGの縁、暗い画像と明るい点、上下段への作用範囲、旧ファイルの読込を確認する。
3. **光の粒子**。シーク順序を変えた同一時刻、保存と再読込、左トリム前後、段移動、上下段の遮蔽、区間終端、複数クリップ同時再生を確認する。
4. **性能と運用**。3段それぞれで3種類を有効にした1080p素材を、基準Macで60秒以上再生・書き出しする。初期目標は30fpsプレビュー、描画要求からGPU完了までの95パーセンタイル33.3ms以内、書き出しの欠落フレーム0、メモリ使用量がキャッシュ上限に応じて頭打ちになること。シーク連打、書き出し取消・再試行、GPUエラー時の一時ファイル処理も確認する。プレビューの解像度低減が必要な場合は計測後に判断し、粒子の時刻と演出パラメーターは共通のままにする。
