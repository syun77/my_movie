# 画像クリップの追加演出（実装提案）

画像クリップごとにガウスブラー、ブルーム、光の粒子を設定する。既存の位置・拡大縮小・回転・拍／トランジェント連動と組み合わせられる。以下の初期値、上限、保存形式、性能目標は提案値。

## 編集画面

「画像・演出」タブでタイムライン上の画像クリップを選び、インスペクターの折りたたみ式「追加演出」を開く。「＋ 演出を追加」から種類を選ぶと初期値で有効になり、その設定を表示する。各演出には有効チェックと削除操作を置く。無効化すると設定を保持したまま描画を止める。1クリップにつき各種類1つで、追加済みの種類はメニューで選択不可にする。フィルターと粒子の合成順は固定し、一覧にもその順序で表示する。

| 演出 | 設定項目（初期値、範囲） | 見え方 |
| --- | --- | --- |
| ガウスブラー | 半径 8 px（0〜64 px） | 選択した画像をぼかす。0で元の画像を使う。 |
| ブルーム | 輝度しきい値 65%（0〜100%）、半径 24 px（1〜96 px）、強さ 60%（0〜200%） | しきい値より明るい部分から光が広がる。強さ0で光を描かない。 |
| 光の粒子 | 個数 40（1〜200）、直径 8 px（2〜32 px）、速さ 60 px/秒（0〜300 px/秒）、色 #FFE2A6、不透明度 65%（0〜100%） | 柔らかい光点が画面内を漂い、明滅する。速さ0で位置を固定し、明滅は続ける。 |

pxは1920×1080の映像を基準とし、素材の元解像度やウィンドウの大きさから独立させる。各数値欄は `DragValueField` を使い、ダブルクリックで直接入力、中ボタンで初期値へ戻す。左右ドラッグ中は仮プレビュー、mouseUpで1回のUndo／自動保存、Escで取消。追加・削除・有効切替・色変更の確定も各1操作とする。編集中の再生位置は維持し、再生ヘッドが対象区間外なら「クリップ区間外」と表示する。

初期版ではクリップ区間全体に一定の設定値を適用する。粒子の動きは時刻から自動生成する。演出のキーフレーム、音声連動、プリセット、演出専用トラックは後続候補とする。

## 合成順と演出の作用範囲

背景 → 画像1 → 画像2 → 画像3 → スペクトラム → 歌詞の順に描く。各画像レイヤー内では次の順序を使う。

1. 既存の手動変形と自動拡大を評価し、画像をキャンバス座標の透明な描画面へ配置する。
2. その画像にだけブラーを適用する。透明画素の色がにじまないよう、プリマルチプライドRGBAをフィルターに渡す。処理範囲はフィルターの裾まで確保し、映像の外側で最終的に切る。画像端は透明側へ自然にぼける。
3. ブラー後の画像からブルームを生成する。線形RGBの輝度にしきい値を適用し、超過分を入力アルファで重み付けしてぼかす。元画像へ光を加算し、ハローのアルファで画像外にも光を残す。フィルターの作業用テクスチャには浮動小数点を使い、SDR範囲への制限は最終出力で行う。
4. 演出済みの画像を下のレイヤーへsource-overで合成し、その上に粒子を描く。粒子は画面座標の発光スプライトで、対象クリップの画像枠の外にも飛ぶ。後から描く上段の画像で隠れ、ブラーやブルームの入力にもならない。スペクトラムと歌詞は全画像・全粒子より前に描く。

画像と演出の有効期間は `start <= t < end`。クリップの素材が欠損している間は画像と演出をまとめてプレビューから省略し、既存の欠損警告と書き出し前検査を使う。

## 保存と粒子の時刻

- `ImageClip.effects` に型付きの `ImageEffects` を持たせる。`blur`、`bloom`、`particles` はそれぞれ任意の値型で、設定値と `isEnabled` を持つ。未追加はnil。画像素材を共有しても、演出はクリップごとに独立する。素材差し替えや段移動では演出を保持する。
- 保存はProjectFile version 5を提案する。version 4の構造はそのまま読んで `effects` の欠落を空として扱い、通常の保存時にversion 5を出力する。演出を含むファイルを古いアプリで開いた際に無視して上書きすることを防ぐ。未知の版や不正データは読込エラーにして、元ファイルを保持する。
- 編集確定と読込で型、有限性、範囲、RGB値を検証する。粒子には固定幅の乱数シードと位相オフセット秒を保存する。Undo／Redoは既存の `ImageTrack` スナップショットに含め、`ImageEditor` のプレビューと確定の通知を再利用する。
- 粒子番号と保存したシードから固定の整数ハッシュで初期位置・速度方向・明滅位相を得る。粒子の時刻は `t − clip.start + phaseOffset`。位置は直進に緩やかな揺れを加え、スプライトが画面外へ出たところで反対側へ回り込ませる。前フレームの状態を持たないため、任意の位置へのシークや同じ時刻の再出力で同じ粒子配置になる。負の位相でも同じ規則で剰余を計算する。
- 左トリムは `phaseOffset` にクリップ開始の差分を足し、残った区間の見え方を保つ。右トリムはオフセットを維持する。クリップ全体を移動すると演出の位相もクリップと一緒に移動する。左トリムの計算はタイムライン操作と開始時刻欄で共有する。

## レンダリング方式

現在は `PreviewView` と `VideoExporter` が同じCore Graphicsの `SceneRenderer` を使う。この構成を、**Metalで最終合成し、画像フィルターにMetalバックエンドのCore Imageを使う共通レンダラー**へ段階的に切り替えることを提案する。

| 方式 | この機能での評価 |
| --- | --- |
| Core Graphics中心＋Core Imageフィルター | 既存コードへの変更が少ない。フィルター結果を各画像・各フレームでCGImage化して戻す場合、GPUとCPUの同期や転送が再生時の負荷になる。 |
| Metal合成＋Core Image（推奨） | 画像フィルターの中間結果をGPU上で使い、Metalで画像・粒子・前景を合成できる。ガウスぼかしはCore Imageを利用し、粒子描画と最終合成にMetalのパイプラインを持つ。 |
| 全工程を独自Metalシェーダーで実装 | ブラーの精度やパスを細かく制御できる。フィルターの自作と色・アルファの検証範囲が広い。計測で特定の処理がボトルネックと判明した段階で個別に検討する。 |

- **共通入力と合成**。編集画面と書き出しで同じフレーム評価を呼び、時刻、変形、演出値、レイヤー順を共有する。作業座標は1920×1080。Core Imageの画像変換とフィルターをMetalテクスチャに出し、粒子はインスタンス描画する。GPU処理は同じデバイス・コマンドバッファに順序どおり記録する。色は入力プロファイルを尊重して線形sRGBで処理し、アルファと座標系は入力境界で統一する。 [AppleのCore Image／Metal連携](https://developer.apple.com/documentation/coreimage/cicontext/render%28_%3Ato%3Acommandbuffer%3Abounds%3Acolorspace%3A%29)
- **既存の前景描画**。歌詞とスペクトラムはCore Text／Core Graphicsの描画を透過テクスチャへ出し、Metalで前景に合成する。歌詞は表示内容・書式・解像度が同じ間は再利用し、スペクトラムは必要な枠だけ更新する。画像のデコードは既存のImageIO経路を利用し、GPU側の画像キャッシュは素材の差し替えや再読込時に無効化する。
- **プレビュー**。`MTKView` は完成テクスチャを16:9で描画する。時刻は音声再生位置を使い、停止中はシークや編集などの変更時に描画する。表示が遅れた場合は最新のプレビュー要求を優先する。シークや素材切替前の要求は世代で識別し、古い結果を採用しない。 [AppleのMTKView](https://developer.apple.com/documentation/metalkit/mtkview)
- **書き出し**。プールから取得したMetal互換のBGRA `CVPixelBuffer` を `CVMetalTextureCache` でテクスチャにし、GPU完了後に既存のAVAssetWriter経路へフレーム順に渡す。フレーム時刻は `index / 30`。キューを制限し、ライターが詰まったら待機する。GPU処理中のテクスチャやライターが保持するバッファを再使用しない。1080p／30fpsと既存の音声結合を維持し、プレビューはsRGB、MP4はRec.709 SDRとして出力変換と色タグを揃える。 [AppleのCVMetalTextureCache](https://developer.apple.com/documentation/corevideo/cvmetaltexturecache-q3j)、[AVFoundationの色設定](https://developer.apple.com/documentation/avfoundation/setting-color-properties-for-a-specific-resolution)
- **負荷と失敗時の扱い**。無効な演出のパスは省略し、処理済み画像と中間テクスチャを再利用する。キャッシュには容量上限を設ける。GPU処理中のフレームは用途ごとに2枚以内から検証を始める。GPUを初期化できない場合や書き出し中の描画失敗は明示し、演出を省いた動画を成功扱いにしない。対象MacでのGPU／エンコーダ動作は実機検証で確定する。

## 実装順と受け入れ条件

1. **技術検証**。透明PNGと3段の画像を使い、同じ共通フレームを `MTKView` とAVAssetWriterへ出す。現行描画と比較して画像の位置・回転・アルファ・歌詞・スペクトラム・音画同期を確認し、圧縮前の画素を同じ色空間に変換してプレビューと出力を比較する。最小対象MacはmacOS 14対応機から選定する。
2. **ブラーとブルーム**。保存・Undo／Redo・数値編集から書き出しまでつなぐ。半径0／強さ0／無効化、透明PNGの縁、暗い画像と明るい点、上下段への作用範囲、旧ファイルの読込を確認する。
3. **光の粒子**。シーク順序を変えた同一時刻、保存と再読込、左トリム前後、段移動、上下段の遮蔽、区間終端、複数クリップ同時再生を確認する。
4. **性能と運用**。3段それぞれで3種類を有効にした1080p素材を、基準Macで60秒以上再生・書き出しする。初期目標は30fpsプレビュー、描画要求からGPU完了までの95パーセンタイル33.3ms以内、書き出しの欠落フレーム0、メモリ使用量がキャッシュ上限に応じて頭打ちになること。シーク連打、書き出し取消・再試行、GPUエラー時の一時ファイル処理も確認する。プレビューの解像度低減が必要な場合は計測後に判断し、粒子の時刻と演出パラメーターは共通のままにする。
