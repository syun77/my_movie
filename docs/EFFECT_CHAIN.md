# 演出チェーン

2026-11-19実装。クリップ内の演出を上から下へ順次適用する。

## 基本ルール

画像・動画・Spine・空クリップに、上から下へ実行する1本の演出チェーンを持たせる。各演出は直前までの結果を受け取り、次の演出へ結果を渡す。別クリップ・歌詞・スペクトラムには作用しない。チェーンの順序はクリップ内の処理順であり、タイムラインの段順は変えない。

基本経路は「素材の取得・基本変形 → 演出チェーン → クリップ共通の不透明度 → 同段クロスフェード → 段間マスク・段合成 → スペクトラム・歌詞 → 出力色変換・ディザ」。素材なしは透明面から開始する。基本の位置・拡縮・回転は固定の入力工程とし、初期版で並べ替えない。

| 種別 | 演出の例 | 処理 |
| --- | --- | --- |
| 加工 | 色調補正、色収差、周辺減光、放射ブラー、ガウスブラー、拡大ループ | そこまでの結果全体を加工して置き換える |
| 発光加工 | ブルーム、クロスグレア | 直前の結果から光を生成し、その結果へ加算する |
| 生成・重ね合わせ | 図形、雪、粒子、集中線、放射光線、レンズフレア、八芒星、ワープ航行など | 生成した映像を直前の結果へ重ねる |
| 背景 | 単色背景 | 直前の結果の背面へ指定色を敷く |
| 全体移動 | シェイク | 直前までの結果全体を画面座標で揺らす |
| 切り抜き | このクリップのマスク | 直前までの結果全体を切り抜く |

2値化も加工として扱う。各演出内の色相→明度/彩度などの処理は1つの演出の内部仕様とし、分割しない。

## 順番で変わる結果

- `雪 → ガウスブラー` は素材と雪の両方がぼける。`ガウスブラー → 雪` は雪が鮮明に残る。
- `放射光線 → 色調補正` は光線も補正する。`色調補正 → 放射光線` は光線の指定色を保つ。
- `マスク → ブルーム` は切り抜いた境界から外へ光がにじむ。`ブルーム → マスク` はにじみも切り抜く。
- `雪 → シェイク` は雪も揺れる。`シェイク → 雪` は素材が揺れ、雪は画面座標に留まる。
- `2値化 → ブルーム` は2色化した明部が発光する。`ブルーム → 2値化` は発光も含めて2色化する。

ブルームとクロスグレアはそれぞれ独立したチェーン項目とする。後ろにある方は前で加えた光も入力として読む。現実装の「同じ素材面から両方を独立抽出」とは異なる新仕様になる。

生成演出の座標・大きさは既存の1080p画面基準を使う。前段のシェイクや拡大ループで、後から追加される粒子の発生座標が移動することはない。後段の加工は生成物にも作用する。

## 編集画面

ドラッグ対象の半透明表示と追従行は [ドラッグ表示](EFFECT_CHAIN_DRAG.md) を参照。

「追加演出」を縦のチェーン一覧へ変更する。「追加演出」は折りたたみのない見出しとし、素材入力・クリップ出力の説明ラベルは表示しない。処理は一覧の上から下へ適用する。

各行はドラッグハンドル、有効チェック、演出名、メニューを持つ。選択した1演出の詳細を一覧の下に表示し、長いチェーンでも数値編集に幅を確保する。同じ演出を再クリックしても詳細を閉じない。選択は保存やUndoの対象外。

- ハンドルを上下ドラッグし、挿入線で移動先を示す。末尾・先頭も挿入可能。
- ドラッグ中は仮順序でプレビューし、mouseUpで1回確定する。Esc・領域外ドロップ・終了準備は取り消す。再生位置は変更しない。
- 行メニューに「上へ移動」「下へ移動」「削除」を用意する。端では移動を無効化する。
- 「＋ 演出を追加」は末尾へ追加し、その演出を選択する。行メニューの「この後に追加」で途中にも挿入できる。
- 有効OFFは完全な通過とし、設定・キー・音楽同期・位置を保持する。順序変更だけで再有効化しない。
- チェーン全体のバイパスを用意し、ON中も内容を編集できる。バイパスはプロジェクトへ保存し、出力にも反映する。

初期版は同じ種類を1クリップに1つまでとし、追加済みの種類は追加メニューで無効にする。分岐、グループ、途中結果のソロ、順序の時刻変化、チェーンプリセット、チェーンだけのコピーは初期版に含めない。

数値操作はDragValueFieldの既存仕様を共有する。並べ替えのために数値欄のドラッグを奪わない。削除はその演出のキー・同期・範囲もまとめて削除し、Undoで全て復元する。

## マスクと不透明度

現在の「自画像マスク」は名称を「このクリップのマスク」とし、チェーンの好きな位置に置ける。粒子なども、その位置までに描かれていれば対象になる。マスク後に追加した生成物には作用しない。

「直下の段をマスク」は別の固定設定へ分離し、チェーンの外、クリップ出力欄に置く。直下固定段の完成結果を切り抜く既存の段間ルールを維持し、同じ設定をチェーンで動かせるようには見せない。マスク用図形・その数値自動化は専用設定として保持する。両マスクは同時使用可能とする。

クリップ共通の不透明度はチェーン完成後に一度だけ適用し、生成物と発光にも同じ倍率を掛ける。演出固有の不透明度はその演出の段階で適用する。不透明度100%の通常合成の生成物は、それ以前の結果を覆う場合がある。

## 保存・自動化・編集履歴

演出の実体を順序付き配列 `effectChain.nodes` に一本化する。各ノードは安定したID、種類を識別するpayload、有効状態を含む種類固有設定、数値項目のキー・音楽同期・表示範囲・位相・seedを持つ。全体バイパスはチェーンが所有する。保存キーはVisualClip.effectChain、内部型はImageEffectsで、種類別プロパティはnodesの読み書き用投影とする。既存ImageEffectsの種類別optionalと並行して順序だけを別管理する構造は採用しない。

自動化の参照は「ノードID＋パラメーター」で識別する。並べ替えはIDも値も変更しない。タイムラインの演出レーンはチェーン順に表示し、演出の高さはノードID＋パラメーターで保持する。同じ段の共有レーンは選択クリップを優先し、その後に他クリップだけが持つ項目を並べる。レイヤーの開閉・選択キーIDは並べ替えで維持する。基本変形・不透明度・Spine専用レーンは既存の固定領域を使用する。

クリップのコピー・複製はノードとキーへ新しいIDを発行し、参照も対応づけて複製する。左トリムはキー時刻と位相を既存と同じ規則で補正する。並べ替え・無効化で時計やseedをリセットしない。

追加・削除・順序変更・有効切替・全体バイパスはそれぞれUndo1回、自動保存1回。仮変更は保存しない。編集と出力を同時実行せず、出力には確定済みスナップショットを渡す。

保存形式はv21、読込はv18〜21。ProjectMigratorの隣接変換で既存のノードID・順序・キー・同期を保持し、原本をバックアップして保存する。変換・検証に失敗したファイルを上書きしない。

## 描画実装の制約

プレビューとMP4は同じチェーン評価器を使う。各時刻の値を共通ParameterEvaluator相当の処理で確定し、ノード順に実行する。生成と加工が混ざっても画面全体をCPUへ読み戻さず、Metal/Core ImageのGPU処理でつなぐ。

透明な中間面に、アルファと発光成分を保って蓄積する。アルファ0でもRGBに光だけが存在する加算演出を、加工処理が誤って捨てないよう、各ノードの入出力契約を統一する。色補正・2値化・発光抽出は一時的な色の基準係数 `max(alpha, min(1, max(R,G,B)))` を使用し、RGBにだけ存在する光も処理する。色補正と2値化は元のalphaを保持する。ブルーム/グレアはcoverageを増やさずRGBを加算する。最終背景への合成まではSDR範囲へ不用意にクランプしない。

ブラー等の余白は後段の参照範囲を含めて確保し、途中で1080p枠へ切ってにじみを失わない。画面基準の中心・マスクは余白により位置が変わらない。出力時に画面枠へ切る。シェイク・拡大ループの画面外サンプルは透明とする。

中間面は寿命を管理して再利用し、ノード数に比例してフルサイズ面を常駐させない。キャッシュは素材フレーム、順序、評価済み設定、時計、seed、解像度を含む。変更前までの結果を再利用できても、順序変更による後段の再評価を省略しない。最適化でブルーム等の入力意味を変えない。1080p/3段でGPU時間を計測する。最小対象Macでのピークメモリと全演出を極端な値で併用した負荷の保証値は未確定。

## 実装範囲と受入条件

26種類を加工・生成とも直列評価し、直下段マスクはクリップタブ最下部の独立カテゴリへ分離する。UI・モデル・自動化・プレビュー・動画出力・移行は同じノードモデルを使用する。

確認する項目:

1. 雪とブラー、光線と色調補正、マスクとブルームの逆順で、意図した差が出る。
2. ブルームとグレアの後段が前段の発光を読む。透明領域上の加算光も後段加工で消失しない。
3. OFF・全体バイパス・削除・取消・Undo/Redo・保存復元が順序と値を正しく保持する。
4. 並べ替えてもキー・同期・レーン選択が別の演出へ移らず、コピーと左トリムでも参照と時計を維持する。
5. 自クリップと直下段のマスク、最終不透明度、通常/加算合成、空クリップ、半透明PNG、動画、Spineを検証する。
6. 余白のある発光・ぼかし、シェイク・拡大ループ、重い演出を交互に置いた3段構成で欠けとメモリ増加を確認する。
7. シーク順に依存せず同時刻が一致し、プレビューとMP4が同じチェーンを使用する。
8. 旧形式の変換順・自動化参照・マスク分離・原本保護をfixtureで確認する。
