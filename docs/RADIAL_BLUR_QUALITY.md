# 放射ブラーの品質改善

2026-11-18実装。`RadialBlurRenderer`と`Scene.metal`の専用compute pipelineをプレビュー・出力で共有する。

## 採用した仕様

- UV距離による元の広がりを維持し、サンプル数からブラー区間を分離する。q(t)=p−(p−c)×min(1,s×|uv−center|)×t、tの積分区間は常に[0,1]。中心を越えて反対側を読むことはない。
- 層化した中点積分を使用する。各区間は1/N幅で同じ重み。台形則は端点に有限の重みが付いて細線の元位置の残像を強めるため採用せず、中点則で連続区間を評価する。
- 軌跡長を実際の処理解像度の画素数Lで求め、N=2×ceil(L/2)を2〜最大回数へ制限する。目標間隔は1px。最大回数は2〜256（初期256）、計算は偶数ペアなので奇数の上限では1つ少ない偶数を使用する。
- 間隔が1pxを超えて疎になると固定ジッターを徐々に適用し、2px以上で最大振幅にする。各層の幅に対して±0.175まで。隣接2サンプルを逆方向に同量ずらし、区間全体の平均位置は常に1/2に保つ。
- ジッターはテクスチャ画素座標とペア番号からの整数hash。時刻・描画履歴・clip IDには依存せず、同じ入力の再描画やシークで同じ結果になる。
- linearサンプラー・領域外透明・線形premultiplied RGBA積分。透明サンプルも分母に含め、alphaによる色の再正規化は行わない。0%または無効ではバイパスする。
- 色調補正/色収差/Vignette後、Gaussian blur/bloom前。CIの回数別ソース生成・コンパイル・全面ROIを廃止した。前処理が不要なら配置済みMetal面を直接読む。前処理面とGaussian blur用の一時出力は再利用し、放射ブラーを使わない描画またはキャッシュ破棄時に解放する。

## 操作・保存

強さ0〜100%、中心X/Yは1080p左上原点。旧「サンプル回数」欄は「最大サンプル回数」とし、自動密度の上限を指定する。既存の値とキー/音楽同期は保持するため、以前の16/64上限もそのまま適用される。既存プロジェクトでも品質を上げたい場合は上限を256へ上げる。新規追加は256。回数を上げても積分区間の長さは変わらないが、離散化誤差やノイズの見え方は変化する。

## 検証結果

`RadialBlurTests`で以下を確認する。

- 中央/画面端中心、上限2/64/128/256で線形勾配をCPU参照と比較。境界補間の影響を分離するため入力周囲2pxを確保したうえで中心越え抑制と平均位置の一致を確認する。
- 1080pの1px線（横17px/縦13pxごと）、premultiplied RGB/alphaで高密度CPU積分と比較。4096点と8192点で赤チャンネルの差が0.001以下になることを確認。
- 160点の評価位置での赤チャンネルRMS（線形0〜1）:

| 最大回数 | RMS誤差 | 単層GPU時間の一例 |
| --- | --- | --- |
| 64 | 0.008353 | 約12ms |
| 128 | 0.005640 | 約19ms |
| 256 | 0.002531 | 約25ms |

256は64比で約70%誤差減。256でジッターを無効にすると0.002806で、この素材では固定ジッターで約10%改善した。特定素材・実行環境での測定で、すべての素材での改善率やGPU時間を保証しない。比較は新方式の上限間の差であり、旧方式との直接測定ではない。

- 同じ入力の再描画、強さ0のバイパス、premultiplied RGBAの比率を確認。
- AppKitの追加/有効切替/削除、数値初期値、共通自動化、保存往復、合成キャッシュを確認。
- 複合フィルター、3段、シーク・キャッシュ破棄後の再現、MP4生成の試験も保持する。

## 残る制約と採否

256点を超える密度が必要な長い軌跡では、1pxの目標間隔には届かず残像や粒状感が残る可能性がある。固定ジッターは時間乱数によるちらつきを作らないが、移動する素材と固定パターンの干渉を完全には除去しない。

今回は多重解像度フィルターを採用しない。密度改善とジッターで参照誤差が減少し、mipmapによる放射方向と直交する細部のぼけを加えずに改善できたため。最大3段の1080p・256点で30fpsを保証するものではなく、プレビューは縮小解像度とキャッシュ、出力は全フレームのGPU完了待ちを使う。画質より速度を優先する場合は上限を下げる。多重解像度化は長い軌跡の細線欠落や実素材での速度が問題となる場合の次の候補。

画素距離で等方的な広がりに変える案と履歴を用いた時間フィルターは未採用。前者は演出形状を変え、後者はシークと出力の再現性の管理が必要になる。実ユーザーの写真・文字・動画素材による主観比較は未実施。
