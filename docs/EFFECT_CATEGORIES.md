# 演出カテゴリ

2026-11-19実装。増えた演出項目をカテゴリごとに選択しやすくする。演出チェーンの追加操作へ適用する。

## 方針

「＋ 演出を追加」をカテゴリ別のサブメニューにする。階層は「カテゴリ → 演出」の1段だけとし、細分類を増やさない。現在の26種類を6カテゴリに整理し、どのカテゴリも2〜6項目で選べるようにする。

カテゴリは見た目の目的で探すための分類であり、描画順・作用対象・保存構造は決めない。演出チェーンの末尾追加と途中追加で同じメニューを利用する。

## 分類と表示順

カテゴリ内は以下の固定順。五十音順ではなく、基本的な演出から関連する演出へ並べる。同じ演出は1カテゴリだけに所属する。

| カテゴリ | 演出（表示順） |
| --- | --- |
| 色・質感 | 色調補正、2値化、Vignette（周辺減光）、色収差、Sobel＋色収差 |
| ぼかし・発光 | ガウスブラー、放射ブラー、ブルーム、クロスグレア、レンズフレア |
| 粒子・天候 | 光の粒子、光の粒子2、舞い上がる火の粉、雪 |
| 効果線 | 集中線、集中線２、集中線３、直線効果線、放射光線 |
| 動き・抽象映像 | シェイク、拡大ループ、八芒星、ワープ航行 |
| 背景・図形・マスク | 単色背景、図形、このクリップのマスク |

集中線２は実装方式より用途を優先し「効果線」に統一する。レンズフレアは光を加える目的から「ぼかし・発光」に置く。

## 追加操作

- 「＋ 演出を追加」を開くと6カテゴリを表示し、各サブメニューから演出を選ぶ。
- 追加済みの演出も元の位置に残し、「追加済み」を付記して無効化する。有効OFFの演出も追加済みとして扱う。初期版は同種1つまでという現仕様を維持する。
- あるカテゴリが全て追加済みなら、カテゴリ名に「すべて追加済み」を付記してサブメニューは開けるようにする。全演出が追加済みでもメニューは開け、状態を確認できる。
- 選択した演出を既定値・有効ONで追加し、その設定を表示する。再生位置は動かさない。追加は既存の確定経路でUndo1回・自動保存1回とする。
- メニューを開く、カテゴリを開く、キャンセルする操作はプレビュー・モデル・履歴・保存を変更しない。
- 編集不可の処理中は追加操作を無効化する。メニュー表示中に対象クリップや編集可能状態が変わった場合は追加確定時に再検証する。
- マウスに加え、macOS標準メニューの矢印キー・Return・Escで操作できるようにする。

演出チェーンでは「＋ 演出を追加」と「この後に追加」の両方でこのメニューを使う。挿入位置だけを呼び出し元から渡し、カテゴリ順でチェーンを並べ替えない。

## 追加済み演出の選択

追加済みのチェーン一覧から行を直接選択する。カテゴリを先に選ばせる操作は追加しない。各演出名の後ろに有効OFFなら「無効」を付記し、既存の有効チェックと状態を一致させる。

追加済み一覧は適用順に表示し、カテゴリ見出しで再編成しない。固定出力設定の「直下段のマスク」はチェーン外の設定ボタンから操作し、追加カテゴリには含めない。

## 状態と実装境界

カテゴリ選択状態はメニューを閉じるたびに解消し、UserDefaultsやプロジェクトに保存しない。カテゴリを追加するだけでは保存バージョンを変更しない。演出の有効状態・キー・音楽同期・数値編集・描画順は既存仕様を使う。

演出の識別子・表示名・所属カテゴリ・表示順を共通の定義へまとめ、末尾追加と途中追加で共有する。追加済み一覧の名前は同じEffectKindの定義を使う。モデルの保存識別子をカテゴリ順に振り直さない。入れ子のNSMenuでは最上位メニューだけへのitem(withTag:)検索に依存せず、モデル更新時に共通生成処理からメニュー全体を作り直し、追加済み表示と有効状態を同期する。追加時はクリップID・編集可否・重複・挿入先ノードの存在を再検証し、古いメニューから別クリップへ追加しない。

初期版は検索・サムネイル・お気に入り・履歴を含めない。項目数がさらに増えてカテゴリ内の探索が長くなった段階で、「検索欄＋カテゴリ一覧＋結果一覧」のポップオーバーを検討する。

## 受入条件

- 現在の26種類が重複・欠落なく1カテゴリずつに所属する。
- 追加済み・有効OFF・未追加・全て追加済みが表示と操作で区別できる。
- 演出の追加後にその詳細が開き、再生位置を保持する。Undo/Redoで設定と自動化を既存どおり復元する。
- クリップ切替・削除・Undo/Redo後もメニューの追加可否とチェーン一覧が実モデルに一致する。
- 最小ウィンドウ・狭いインスペクターでも演出名と数値欄を操作でき、キーボードとVoiceOverでカテゴリ名・演出名・無効状態が分かる。
- 分類や表示順の変更だけではプロジェクト内容・プレビュー・出力結果を変えない。
